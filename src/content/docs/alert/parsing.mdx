<Callout variant="info" title="Where this fits in Alert">
<DefineTerm term="Parsing" /> is the third pillar of the Alert chapter. Detection mechanisms explained how the engine decided. Validation tested whether the signal is real. Parsing extracts the <DefineTerm term="Metadata" display="metadata" /> at the level of detail the rest of the investigation needs. Without it, the analyst is working with an abstraction.
</Callout>

This matters because adversaries hide their intent inside the very fields you would parse. An EDR alert might report `powershell.exe` executing with an encoded command parameter. Without parsing, the underlying command (and the attacker's intent) stays obscured.

## What parsing has to handle

Modern SOCs ingest logs from legacy <DefineTerm term="Syslog" display="syslog" /> all the way to cloud-native JSON. Parsing frameworks have to normalize that into queryable, structured data, and they have to do it while the adversary is actively trying to hide.

<div class="evasion-grid-blue">
  <div class="evasion-blue-card">
    <h4>Obfuscated scripts</h4>
    <p>PowerShell or Python encoded to dodge plain-text matching.</p>
  </div>
  <div class="evasion-blue-card">
    <h4>Fileless malware</h4>
    <p>Payloads that live in memory with minimal on-disk footprint.</p>
  </div>
  <div class="evasion-blue-card">
    <h4>Living off the land</h4>
    <p>Native binaries executing malicious operations under their legitimate signature.</p>
  </div>
  <div class="evasion-blue-card">
    <h4>Partial metadata</h4>
    <p>Alerts with truncated command lines, missing parent process information, or incomplete context.</p>
  </div>
</div>

Good parsing decodes these patterns while preserving the context downstream phases need.

## Three categories of information from every alert

Whatever surface you are parsing, the output should populate three buckets:

<div class="info-buckets">
  <div class="info-bucket">
    <span class="info-bucket__label">Alert metadata</span>
    <p>Who saw it, when, how confident, what bucket it fits.</p>
    <ul>
      <li>Alert ID and timestamp for unique identification and temporal sequencing.</li>
      <li>Source system and detection mechanism (which engine fired, under what logic).</li>
      <li>Severity and confidence to guide triage priority.</li>
      <li>Category and classification (privilege escalation, lateral movement, exfiltration).</li>
    </ul>
  </div>

  <div class="info-bucket">
    <span class="info-bucket__label">Technical detail</span>
    <p>The investigative substance.</p>
    <ul>
      <li>Affected systems and accounts (endpoints, servers, identities involved).</li>
      <li>Network information (IPs, ports, protocols, session IDs).</li>
      <li>File and process information (paths, hashes, command-line parameters).</li>
      <li>Registry and configuration changes (persistence, policy mods, drift).</li>
    </ul>
  </div>

  <div class="info-bucket">
    <span class="info-bucket__label">Contextual enrichment</span>
    <p>The organizational lens.</p>
    <ul>
      <li>Business impact (what does this potentially disrupt).</li>
      <li>Regulatory implications (HIPAA, PCI DSS, GDPR triggers).</li>
      <li>Historical correlation (does this fit a recurring pattern or campaign).</li>
      <li>Threat intelligence (known IoCs, adversary TTPs, campaign signatures).</li>
    </ul>
  </div>
</div>
