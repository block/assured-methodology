## What to look for: inspection

Common <DefineTerm term="Obfuscation" display="obfuscation" /> patterns observed in frameworks like <DefineTerm term="PowerShell" /> Empire and <DefineTerm term="Cobalt Strike" />:

<div class="obfuscation-grid">
  <div class="obfuscation-card">
    <h3>Base64 encoding</h3>
    <code>powershell.exe -EncodedCommand &lt;long-base64-string&gt;</code>
    <p>The encoded blob hides the actual command from plain-text matching.</p>
  </div>
  <div class="obfuscation-card">
    <h3>Caret insertion</h3>
    <code>cmd.exe /c e^ch^o "Hello"</code>
    <p>cmd strips the escape carets before execution, so the command runs normally while breaking naive substring signatures.</p>
  </div>
  <div class="obfuscation-card">
    <h3>Variable expansion</h3>
    <code>$env:COMSPEC</code>
    <p>Uses environment variables to mask binary references.</p>
  </div>
</div>

Adversaries also abuse trusted system binaries: <DefineTerm term="LOLBins" display="LOLBins" /> such as `certutil.exe` for downloads, `regsvr32.exe` for DLL execution, `bitsadmin.exe` for transfers. These leave minimal forensic footprint because the binary itself is signed and trusted.

<Callout variant="warn" title="Educational, not operational">
The examples in this chapter are illustrative. We deliberately do not show fully working invocation strings. Analysts need to recognize the *shape* of adversary technique, not have a copy-pasteable cookbook. If you need to test detections, use isolated lab environments and sanctioned red-team tools.
</Callout>

## Execution context

The same command can be benign or malicious depending on context. Four contextual signals matter most:

<div class="context-grid">
  <div class="context-card">
    <span class="context-card__label">01 · User context</span>
    <p><code>NT AUTHORITY\SYSTEM</code> vs. a standard user account. System-level execution from a user-initiated process is rarely legitimate.</p>
  </div>
  <div class="context-card">
    <span class="context-card__label">02 · Timing</span>
    <p>Outside business hours vs. scheduled maintenance window. Cross-reference with change tickets and the user's known patterns.</p>
  </div>
  <div class="context-card">
    <span class="context-card__label">03 · Parent process</span>
    <p><code>cmd.exe</code> spawned by <code>outlook.exe</code> is suspicious. The same command from Task Scheduler is usually legitimate.</p>
  </div>
  <div class="context-card">
    <span class="context-card__label">04 · Directory</span>
    <p><code>C:\Windows\Temp</code> or <code>%APPDATA%</code> is suspicious. <code>C:\Program Files</code> is expected.</p>
  </div>
</div>

<Reveal summary="Example: PowerShell from Outlook">
A PowerShell script launched by Outlook signals likely macro <DefineTerm term="Execution" display="execution" /> from an email attachment. What you would check next:

- The Outlook session's recent attachment activity.
- The script's <DefineTerm term="Command Line" display="command line" /> for download cradle patterns.
- Outbound network activity from PowerShell in the next 60 seconds.
- Whether the <DefineTerm term="User" display="user" />'s mailbox shows similar emails to other recipients.

The same PowerShell command from Task Scheduler during a maintenance window is almost certainly legitimate. Same command, different parent, different verdict.
</Reveal>

## Pattern recognition

Build mental patterns for atypical use of common binaries. These are the shapes you want to recognize before reading the command in detail.

<div class="pattern-list">
  <div class="pattern-item">
    <span class="pattern-item__bullet"></span>
    <div>
      <strong>Unusual LOLBin invocations.</strong> <code>rundll32.exe</code>, <code>mshta.exe</code>, <code>wmic.exe</code>, <code>regsvr32.exe</code> invoked outside their normal contexts.
    </div>
  </div>
  <div class="pattern-item">
    <span class="pattern-item__bullet"></span>
    <div>
      <strong>Framework flags.</strong> Command-line flags that suggest framework use: <code>-NoP</code>, <code>-EncodedCommand</code>, <code>-WindowStyle Hidden</code>, <code>-NonInteractive</code>.
    </div>
  </div>
  <div class="pattern-item">
    <span class="pattern-item__bullet"></span>
    <div>
      <strong>Indirect execution.</strong> A trusted binary loading attacker-controlled content from a remote location. The binary is legitimate. The payload is not.
    </div>
  </div>
</div>

<KeyTakeaway>
<DefineTerm term="Command Line Analysis" display="Command line analysis" /> is where <DefineTerm term="Parsing" display="parsing" /> becomes investigation. Decoding what a process is actually doing, past the obfuscation, past the trust signals, anchors everything downstream.
</KeyTakeaway>
