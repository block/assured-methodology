<Quiz title="Quiz: did the chapter stick?" subtitle="No grades. The point is to push your thinking. Some questions are harder than they look.">

  <QuizItem
    prompt="An EDR fires a behavioral alert at 02:14 with 64% confidence. The user's baseline shows they routinely work overnight. What is the right next step?"
    options={[
      { value: "close",      label: "Close as a false-positive. The baseline explains it." },
      { value: "escalate",   label: "Escalate immediately. 02:14 is suspicious enough." },
      { value: "validate",   label: "Run validation across the other three dimensions before deciding." },
      { value: "parse",      label: "Decode the command line in full before doing anything else." },
    ]}
    answer="validate"
    explanation="Baseline comparison is one of three strategies, and one of four dimensions. A single dimension agreeing is not the same as validation. The environmental dimension says the timing is consistent; technical fidelity, threat intelligence, and business impact have not been checked yet. Validate across all four, then decide."
  />

  <QuizItem
    prompt="Two alerts fire with identical content. Alert A is on a contractor's sandbox laptop. Alert B is on a service account with administrative access to a HIPAA-bound database. The analyst can only investigate one in the next 15 minutes. Which strategy makes the prioritization defensible?"
    options={[
      { value: "baseline",    label: "Baseline comparison. The deviations might differ." },
      { value: "chains",      label: "Attack-chain correlation. One of them might be part of a sequence." },
      { value: "criticality", label: "Asset and user criticality. The blast radius is what differs." },
      { value: "fifo",        label: "Queue order. Investigate whichever alert fired first; consistent FIFO handling is defensible." },
    ]}
    answer="criticality"
    explanation="Criticality validation is exactly the strategy designed for this trade-off. Alert B affects a high-criticality asset and a privileged identity, so it is the immediate-action alert. Months later, the criticality data attached to the queue order is what makes the choice reviewable in a post-mortem."
    hint="The two alerts are identical in shape. What differs is the entity each one affects."
  />

  <QuizItem
    prompt="Which detection family is most likely to fire when an adversary uses living-off-the-land binaries with no custom malware?"
    options={[
      { value: "signature",  label: "Signature-based" },
      { value: "anomaly",    label: "Anomaly-based" },
      { value: "rule",       label: "Rule-based" },
      { value: "behavioral", label: "Behavioral analytics" },
    ]}
    answer="behavioral"
    explanation="Signature engines see only signed, trusted binaries. Anomaly engines may not flag because the individual events fall within tolerance. Rule engines can fire if a rule is well-written for the pattern, but they require someone to have written that rule. Behavioral analytics is the family designed for multi-step adversary patterns built from legitimate-looking pieces."
    hint="Think about what each family is naturally good at and what each one is naturally blind to."
  />

  <QuizItem
    prompt="A signature engine reports an exact match on a known-bad SHA-256. At the same moment, a UEBA engine flags the same host for 'unusual process activity'. Before any investigation, how should the analyst calibrate trust in the two signals?"
    options={[
      { value: "equal",     label: "Treat both equally; every alert deserves identical skepticism until validated." },
      { value: "signature", label: "The exact-match signature hit carries high default confidence; the anomaly is genuine signal but ambiguous until corroborated." },
      { value: "anomaly",   label: "The anomaly deserves more trust; it is learned from this environment while signatures are generic." },
      { value: "recent",    label: "Whichever engine was tuned most recently reflects current adversary technique and should be trusted more." },
    ]}
    answer="signature"
    explanation="This is the trust-calibration table from the detection-mechanisms page. Signature means high confidence on exact indicator matches with narrow scope; anomaly means genuine but ambiguous signal that almost always needs corroboration before action. Treating them equally throws away the provenance information the alerts already carry."
    hint="The chapter assigns each detection family a default confidence before any investigation begins."
  />

  <QuizItem
    prompt="An alert reports an outbound TLS connection to a domain registered three days ago. The process is signed certutil.exe. The user is a developer. Which combination of signals would raise the confidence that this is malicious?"
    options={[
      { value: "domain-age", label: "The domain age alone. Domains registered within a week are suspicious enough to act on." },
      { value: "process",    label: "The process alone. certutil making any outbound TLS connection is suspicious enough to act on." },
      { value: "combined",   label: "Domain age, plus certutil, plus no documented build process that uses certutil for downloads." },
      { value: "ignore",     label: "None. The binary is signed by Microsoft, so the activity is trusted regardless of destination." },
    ]}
    answer="combined"
    explanation="Single signals get tuned out as noise. The combination is what changes the verdict. New domain + an unusual process for the user + no documented business reason maps to the classic certutil-as-LOLBin pattern. None of the signals on its own is decisive. The combination is."
  />

  <QuizItem
    prompt={'An EDR alert shows: powershell.exe -nop -w hidden -enc SQBFAFgAIAAoAE4AZQB3AC0ATwBiAGoAZQBjAHQA... What does -enc tell you, and what is the right parsing move?'}
    options={[
      { value: "encrypted", label: "The payload is encrypted. Without the key, judge the alert on the parent process alone." },
      { value: "decode",    label: "The payload is Base64 of UTF-16LE text. Decode it; the decoded command decides the verdict." },
      { value: "malicious", label: "The flag itself is the verdict. -enc only exists for attackers, so this alert is a true positive." },
      { value: "benign",    label: "The flag is administrative noise. Plenty of vendor tooling uses -enc; drop it from the parse." },
    ]}
    answer="decode"
    explanation="-EncodedCommand takes a Base64-encoded UTF-16LE string, an encoding, not encryption, so it decodes locally with no key. The surrounding flags (-nop, -w hidden, abbreviated names) raise suspicion, and legitimate automation does use -enc, which is exactly why the decoded payload, not the flag, decides. Here it opens with IEX (New-Object ..., the classic download-and-execute-in-memory prefix."
    hint="Encoded and encrypted are different words for a reason."
  />

  <QuizItem
    prompt="A parsed process tree reads: explorer.exe → WINWORD.EXE → msdt.exe → sdiagnhost.exe. Which link is the anomaly?"
    options={[
      { value: "explorer", label: "explorer.exe → WINWORD.EXE. Word should be launched by the Office click-to-run service." },
      { value: "winword",  label: "WINWORD.EXE → msdt.exe. A document reader spawning a diagnostic tool is the anomaly." },
      { value: "msdt",     label: "msdt.exe → sdiagnhost.exe. The diagnostic tool should never spawn a scripted host." },
      { value: "none",     label: "None. Every process in the chain is a signed Microsoft binary, so the chain is expected." },
    ]}
    answer="winword"
    explanation="explorer.exe launching Word is a user double-click, normal. And once msdt.exe runs, sdiagnhost.exe is its expected child. The break in the story is the middle link: a word processor has no business spawning the Microsoft Support Diagnostic Tool, and that parent-child pair is the signature of the Follina exploit (CVE-2022-30190). Every node being signed by Microsoft is exactly why lineage, not identity, is what you parse."
    hint="Ask what business each parent has spawning its child."
  />

  <QuizItem
    prompt="An analyst pivots to Windows Security Event 4688 to reconstruct process creations, but the CommandLine field is blank on every event. What is the most likely reason?"
    options={[
      { value: "fileless",  label: "The activity was fileless, so there were no command lines to record in the event." },
      { value: "policy",    label: "Command-line capture is a separate audit policy that is off by default and was never enabled." },
      { value: "cleared",   label: "The attacker selectively cleared the field, which is why the rest of the event survived." },
      { value: "sysmon",    label: "Event 4688 has no command-line field at all; only Sysmon Event 1 can record one." },
    ]}
    answer="policy"
    explanation="4688 does have a CommandLine field, but populating it requires the 'Include command line in process creation events' policy, which is off by default. If it was never enabled, every historical event is blank and no retroactive fix exists, a telemetry gap you discover exactly when you need the data. Sysmon Event 1 is the common compensating source. This is why parsing includes knowing what your telemetry was configured to capture."
  />

  <QuizItem
    prompt="What is the Alert phase's deliverable to the rest of the methodology?"
    options={[
      { value: "verdict",     label: "A verdict on whether the alert is malicious, with the reasoning that supports it." },
      { value: "structured",  label: "A structured, validated, parsed record, plus an entity list and an investigation plan." },
      { value: "containment", label: "A containment recommendation for the affected host, ready for IR to execute." },
      { value: "report",      label: "A written report for the security manager summarizing what fired and why it matters." },
    ]}
    answer="structured"
    explanation="Alert produces three things: a structured record of what the engine saw, a validation result that says whether the signal is real, and a parsed metadata set that the next phases can query. Verdicts and containment are downstream phases. Reports are documentation. The Alert phase's job is to make the next analyst's work fast and accurate, not to draw conclusions."
  />
