  <QuizItem
    prompt="An analyst pulls a suspicious binary off a host into a personal scratch directory while working the case, then uploads it to the case-management system at close. What happened to the artifact?"
    options={[
      { value: "fine",  label: "Nothing, as long as the file's contents did not change between acquisition and the upload." },
      { value: "hash",  label: "It is fine if the analyst hashes the file at upload; that hash is what proves its integrity." },
      { value: "ir",    label: "Nothing at triage. Chain of custody is IR's responsibility, and it only starts once the case escalates." },
      { value: "break", label: "The chain of custody broke: nothing records who held the file, its hash, or access in that gap." },
    ]}
    answer="break"
    explanation="The chain is the continuous, time-stamped trail from acquisition onward: identifier, acquisition details, every transfer with re-verification, access log, disposal. A personal scratch directory is one of the most common silent breaks: the analyst held the file the whole time, but nothing documents that stretch. A hash at upload proves nothing about the gap before it; the hash has to be recorded at acquisition and re-verified at each move. In practice a gap usually goes to the weight the evidence carries rather than automatic exclusion, but it invites challenge. And custody starts at acquisition, not escalation: if the case might end with IR or external counsel, treat every artifact as evidence from the moment it is collected."

    prompt="A closure record includes full log excerpts containing customer PII, on the reasoning that the excerpts are the evidence. What does the standard say?"
    options={[
      { value: "keep",     label: "Keep them. Inside a security system of record, completeness outranks the privacy question." },
      { value: "prose",    label: "Drop the excerpts and describe them in prose; raw logs never belong in the record at all." },
      { value: "sanitize", label: "Sanitize what it does not need: a record can be complete and still be a data exposure." },

    ]}
    answer="sanitize"
    explanation="Sanitization mistakes are a named pitfall: a record that copies PII, regulated data, or sensitive operational detail into places that do not need it is complete and a data exposure at the same time. Dropping the evidence entirely fails in the other direction, and encryption at rest does not change who can read the record through the system it lives in."

  <QuizItem
    prompt="A record reads: 'powershell.exe (parent explorer.exe) started at 09:11:41 UTC on laptop-finance-09, one second after a RunMRU write, indicating paste-and-run initial access.' What does the clarity standard say about this sentence?"
    options={[
      { value: "good",    label: "It is exactly right. One sentence carrying observation and conclusion is efficient documentation." },
      { value: "split",   label: "Split and label it: the process event is a fact, the initial-access reading is analysis." },
      { value: "fact",    label: "Delete the second half. Analysis belongs to IR, and a triage record holds facts only." },
      { value: "passive", label: "The problem is voice, not content: rewrite it in the passive voice for objectivity." },
    ]}
    answer="split"
    explanation="The first half is a fact: observable, timestamped, checkable against telemetry. The second half is analysis, a reading of the fact that could change. The standard asks for both, labeled as which is which, so a reviewer can revisit the analysis when new evidence lands without re-litigating the facts. Fused together, a wrong conclusion contaminates a correct observation. Triage records absolutely include analysis (that reasoning is what the replay test depends on), and the voice rule points the other way: active voice, naming who did what."

  <QuizItem
    prompt="A decision header labels the whole case 'High confidence'. The execution chain is corroborated by two independent sources; the attribution rests on a single hash match. What does the confidence rubric object to?"
    options={[
      { value: "round", label: "Nothing that rounding cannot fix: drop the whole case to Medium to stay conservative." },
      { value: "likelihood", label: "The label is redundant: confidence is already captured in the likelihood rating." },
      { value: "claims", label: "Label the claims, not the case: the chain is High and the attribution is Low." },
      { value: "none", label: "Nothing. High is right, because the strongest evidence in the case sets the label." },
    ]}
    answer="claims"
    explanation="The rubric's first rule is to label the claim, not the case. A record usually carries several claims at different confidence levels, and one case-level label hides exactly what the next reader needs: here the execution chain is High (direct, corroborated, alternatives ruled out) and the attribution is Low (one indicator). Rounding the whole case down hides the same information in the other direction. And confidence is recorded beside likelihood, not folded into it: likelihood is how probable it is that the activity is malicious, confidence is how well the evidence supports that judgment."

Leaving it out loses evidence the close rests on, and burying it in an appendix hides it from the correlation that should find it. Recording it as known-good keeps it findable and routes it to the allowlist or warninglist."
