<Quiz title="Documentation chapter quiz">

  <QuizItem
    prompt="When should documentation be written?"
    options={[
      { value: "before", label: "Before the investigation, as a plan." },
      { value: "during", label: "During the investigation, with cleanup at the end. Memory is the freshest while the work is happening." },
      { value: "after", label: "After closure, when there is time to write properly." },
      { value: "review", label: "Only during the manager's review." },
    ]}
    answer="during"
    explanation="Documentation written during the investigation captures detail that is gone an hour later. Post-hoc documentation reads tidy and is less useful for training, audit, or trend analysis."
  />

  <QuizItem
    prompt="Which is the biggest documentation pitfall?"
    options={[
      { value: "length", label: "Records are too long." },
      { value: "form", label: "Treating the form as the work. Long records with no substance are worse than short ones with substance." },
      { value: "speed", label: "Writing too quickly." },
      { value: "templates", label: "Using templates." },
    ]}
    answer="form"
    explanation="The most common failure is filling the template without recording the reasoning. The form is scaffolding, not the goal. A short, complete record beats a long, empty one every time."
  />

  <QuizItem
    prompt="What is the test of good documentation?"
    options={[
      { value: "length", label: "Length." },
      { value: "format", label: "It follows the template exactly." },
      { value: "replay", label: "A future reader can replay the analyst's reasoning without asking questions." },
      { value: "speed", label: "How quickly it was written." },
    ]}
    answer="replay"
    explanation="The test is whether the record stands alone. A future analyst, auditor, or trainer should be able to read it and understand both what was decided and why. Length and speed are secondary."
  />

  <QuizItem
    prompt="A closed false-positive case is documented. What is its main downstream use?"
    options={[
      { value: "compliance", label: "Compliance evidence." },
      { value: "trash", label: "It has no use; close it and move on." },
      { value: "detection", label: "Feedback for detection engineering and a training case for the team. False positives are sharpening signals when documented." },
      { value: "manager", label: "Performance review material." },
    ]}
    answer="detection"
    explanation="Closed false positives, well documented, point at where the detection logic could be sharper and help newer analysts learn what to look for. The methodology treats them as contributions, not as non-events."
  />

</Quiz>
