  <QuizItem
    prompt="What is the difference between event triage and incident response?"
    options={[
      { value: "size", label: "Triage is small cases; IR is big cases." },
      { value: "team", label: "Triage is junior analysts; IR is senior." },
      { value: "question", label: "Triage frames the puzzle ('what is this?'). IR completes it ('how do we stop it?'). Different questions, different mindsets, different outputs." },
      { value: "same", label: "They are the same work with different names." },
    ]}
    answer="question"
    explanation="The distinction is about the question being asked. Triage is 'what is going on.' IR is 'what do we do about it.' Conflating them leads to premature escalation or stalled investigations."

  <QuizItem
    prompt="The handoff packet should be optimized for..."
    options={[
      { value: "brevity", label: "Brevity. Keep it short." },
      { value: "completeness", label: "Letting the next analyst start where this one stopped. Brevity matters; clarity matters more." },
      { value: "compliance", label: "Compliance reporting." },
      { value: "manager", label: "The SOC manager's review." },
    ]}
    answer="completeness"
    explanation="The packet is the bridge between triage and IR. The metric is whether the next tier can act without asking the triage analyst to re-explain. Brevity is good; completeness is the goal."
  />

  <QuizItem

  <QuizItem
    prompt="The terms 'event', 'alert', and 'incident' get used interchangeably in casual conversation. How does ASSURED distinguish them?"
    options={[
      { value: "same", label: "They mean the same thing in mature SOCs." },
      { value: "size", label: "Event is small, alert is medium, incident is large." },
      { value: "structural", label: "Event is a point-in-time observation (neutral). Alert is an event meeting a threshold requiring action. Incident is a negative event with correlated alerts requiring intervention. Each term carries distinct operational meaning." },
      { value: "tooling", label: "They map to different tools." },
    ]}
    answer="structural"
    explanation="ASSURED treats them as distinct concepts with distinct operational meaning. Events are raw observability data. Alerts cross a threshold and become SOC work. Incidents are correlated alerts representing business-impacting issues that require coordinated response. Conflating them loses precision under pressure."
  />

  <QuizItem
    prompt="Lateral movement into systems outside the original Scope boundary appears during Uncover. What is the right escalation behavior?"
    options={[
      { value: "ignore", label: "Ignore the out-of-scope finding." },
      { value: "escalate", label: "Escalate immediately and let IR handle the expanded scope." },
      { value: "loop", label: "Treat it as a trigger for the dynamic loop: refine Scope, re-run Uncover, re-evaluate Risk. Escalate only if the expanded picture meets criteria." },
      { value: "close", label: "Close the case and open a new one." },
    ]}
    answer="loop"
    explanation="Lateral movement into unscoped systems is a classic dynamic-loop trigger. The methodology requires returning to Scope with refined boundaries, re-running Uncover on the expanded frame, and re-evaluating Risk. Escalation criteria are then applied to the broader picture, not just the initial finding. Skipping the loop produces escalations based on incomplete pictures."
  />

  <QuizItem
    prompt="Your handoff packet has eight strong sections, but you noticed during the case that you forgot to log the 14:02 page to your SOC manager. What is the right call?"
    options={[
      { value: "skip", label: "Skip it; managers already know they were paged." },
      { value: "verbal", label: "Mention it verbally during the IR handoff but don't update the packet." },
      { value: "add", label: "Add the entry to the Communication record section with the actual timestamps; that's exactly what the section exists for." },
      { value: "amend", label: "Amend only after IR closes the case, since the audit happens later." },
    ]}
    answer="add"
    explanation="The Communication record is the ninth section of the handoff packet for exactly this reason. Backfilling notifications (who, on which channel, when) with real timestamps prevents duplicate pages, gives IR an instant view of who already knows, and starts the audit trail before memory fades. Verbal handoffs and post-close amendments both lose information."
  />
