  <QuizItem
    prompt="What is the difference between event triage and incident response?"
    options={[
      { value: "size", label: "Scale: triage handles single-host cases, and IR takes over once multiple systems are involved." },
      { value: "team", label: "Seniority: triage is the analyst queue, and IR is where the senior responders sit." },
      { value: "question", label: "The question: triage asks what is this, IR asks how do we stop it. Different outputs follow." },

    ]}
    answer="question"
    explanation="The distinction is about the question being asked. Triage is 'what is going on.' IR is 'what do we do about it.' Conflating them leads to premature escalation or stalled investigations."

  <QuizItem

    options={[

  <QuizItem
    prompt="The terms 'event', 'alert', and 'incident' get used interchangeably in casual conversation. How does ASSURED distinguish them?"
    options={[
      { value: "same", label: "They are synonyms in practice; mature SOCs standardize on whichever term the tooling uses." },
      { value: "size", label: "Magnitude: an event is small, an alert is medium, and an incident is organization-scale." },
      { value: "structural", label: "Events are neutral observations; alerts cross an action threshold; incidents require intervention." },
      { value: "tooling", label: "Source: events come from log pipelines, alerts from the SIEM, incidents from the ticketing system." },
    ]}
    answer="structural"
    explanation="ASSURED treats them as distinct concepts with distinct operational meaning. Events are raw observability data. Alerts cross a threshold and become SOC work. An incident is a violation, or imminent threat of violation, of security policy or standard security practice (NIST SP 800-61), typically confirmed out of one or more alerts and requiring coordinated response. Conflating them loses precision under pressure."
  />

  <QuizItem
    prompt="Uncover confirms lateral movement into systems outside the original Scope boundary. What is the right escalation behavior?"
    options={[
      { value: "ignore", label: "Note the finding but keep working the original boundary; out-of-scope systems are a separate case." },
      { value: "escalate", label: "Escalate immediately, it is a canonical criterion, and keep the loop running in parallel for IR." },
      { value: "loop", label: "Refine Scope, re-run Uncover, re-evaluate Risk, and escalate only if the expanded picture still meets criteria." },
      { value: "close", label: "Close this case and open a fresh one scoped to the newly discovered systems from the start." },
    ]}
    answer="escalate"
    explanation="Confirmed lateral movement is one of the four canonical criteria, and the break-glass rule fires the moment a criterion is confirmed, from any phase. A spreading compromise is IR's problem to contain while investigation continues. The dynamic loop still matters: refining Scope and re-running Uncover is exactly the scoping support IR needs next, but it happens in parallel under IR's clock, not as a precondition for escalating. Deferring escalation through a full loop iteration while a compromise spreads is the failure mode the criteria exist to prevent."
  />

  <QuizItem
    prompt="Your handoff packet has eight strong sections, but you noticed during the case that you forgot to log the 14:02 page to your SOC manager. What is the right call?"
    options={[
      { value: "skip", label: "Skip it. The manager knows they were paged, and the packet documents the case, not the chatter." },
      { value: "verbal", label: "Mention it verbally during the IR handoff so the responders know, but leave the packet as-is." },
      { value: "add", label: "Add it to the Communication record with the real timestamps; that section exists for this." },
      { value: "amend", label: "Amend the packet after IR closes the case, when the audit review actually needs the entry." },
    ]}
    answer="add"
    explanation="The Communication record is the ninth section of the handoff packet for exactly this reason. Backfilling notifications (who, on which channel, when) with real timestamps prevents duplicate pages, gives IR an instant view of who already knows, and starts the audit trail before memory fades. Verbal handoffs and post-close amendments both lose information."
  />
