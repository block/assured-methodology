<section id="A" class="clear-section">

<h2>A</h2>

<dl class="clear-terms">
<dt>Access Control</dt><dd>Rules and procedures that regulate who can access certain systems, data, or resources.</dd>
<dt>Access Pattern</dt><dd>The way a user or system interacts with resources, such as login times, frequency of access, and volume of data transferred.</dd>
<dt>Advanced Persistent Threat (APT)</dt><dd>A sophisticated cyber attacker, often state-sponsored, who gains and maintains unauthorized access to networks for extended periods while avoiding detection.</dd>
<dt>AI/ML (Artificial Intelligence / Machine Learning)</dt><dd>Technologies that enable systems to learn from and make decisions based on data, used in security for threat detection, pattern recognition, and automated response.</dd>
<dt>Alert</dt><dd>An automated notification produced when detection logic decides an event might be malicious, anomalous, or in violation of policy. The detection engine's hypothesis, not a verdict; the analyst makes the call.</dd>
<dt>Alert De-duplication</dt><dd>The process of consolidating multiple identical or related alerts into a single notification to reduce noise and improve analyst efficiency.</dd>
<dt>Alert Fatigue</dt><dd>The desensitization of security analysts to alerts due to high volumes of notifications, potentially leading to missed critical threats.</dd>
<dt>Alert Parsing</dt><dd>The systematic process of breaking down and analyzing the components of a security alert to understand its technical details and significance.</dd>
<dt>Alert Validation</dt><dd>The step where an alert is examined and confirmed as legitimate or false-positive before initiating further investigation or response.</dd>
<dt>Analyst Burnout</dt><dd>Physical and mental exhaustion experienced by security analysts due to high-stress environments, constant alert monitoring, and pressure to maintain security.</dd>
<dt>Anomaly</dt><dd>An observation that deviates from an established baseline. Anomalies are statistical, not malicious; an analyst still has to decide whether the deviation matters.</dd>
<dt>Anomaly-Based Detection</dt><dd>A security detection method that identifies suspicious activity by comparing current behavior against established baselines of normal activity.</dd>
<dt>Application-Layer Protocol</dt><dd>Network protocols that operate at Layer 7 of the OSI model, dealing with application-specific communication (HTTP, SMTP, DNS).</dd>
<dt>Application Programming Interface (API)</dt><dd>A set of rules and protocols that allows different software systems to communicate with each other.</dd>
<dt>Arbitrary Commands</dt><dd>Unauthorized commands that an attacker can execute on a compromised system, often with the same privileges as the compromised application.</dd>
<dt>Artifacts</dt><dd>Digital evidence or traces left behind by system activity or security incidents, used in forensic analysis and incident investigation.</dd>
<dt>Asset</dt><dd>Something the organization owns, depends on, or is accountable for: data, a system, an identity, a credential, or a service. An asset's criticality is what turns a generic alert into a prioritized one.</dd>
<dt>Asset Criticality</dt><dd>The level of importance or sensitivity of an asset, which determines the level of protection it requires.</dd>
<dt>Asset Role</dt><dd>The defined function or purpose of an asset within an organization, helping prioritize its security importance.</dd>
<dt>ASSURED Methodology</dt><dd>A structured approach to event triage in security operations, comprising seven phases: Alert, Subject, Scope, Uncover, Risk, Escalation, and Documentation.</dd>
<dt>Attack Chain</dt><dd>The ordered sequence of steps an attacker takes from initial access through their objective. Useful as a framework (Lockheed Martin's Kill Chain, MITRE ATT&amp;CK's tactics) because it lets defenders intervene at any link, not only the first.</dd>
<dt>Attack Patterns</dt><dd>Common techniques or behaviors used by attackers that help in recognizing and defending against threats.</dd>
<dt>Attack Vector</dt><dd>The entry point an attacker uses to reach a target: a phishing email, an exposed RDP port, a third-party vendor with trusted access, a misconfigured cloud bucket. Each vector implies a different control to harden.</dd>
<dt>Attribute-Based Access Control (ABAC)</dt><dd>Restricts access based on user attributes, environment conditions, and resource characteristics to enforce fine-grained security policies.</dd>
<dt>Authentication</dt><dd>Proving who you are to a system: a password, a hardware token, a biometric, a certificate. Distinct from authorization, which is what that identity is then allowed to do.</dd>
<dt>Authorization</dt><dd>The process of granting or denying access to resources based on a user's or system's identity and permissions.</dd>
<dt>Automation</dt><dd>The use of technology to perform security tasks with minimal human intervention, including alert triage, incident response, and threat hunting.</dd>
<dt>Autonomous System Number (ASN)</dt><dd>A unique identifier assigned to an internet network used for routing traffic between networks.</dd>
</dl>

</section>

<section id="B" class="clear-section">

<h2>B</h2>

<dl class="clear-terms">
<dt>Base64 Encoding</dt><dd>A binary-to-text encoding scheme used to represent binary data using a set of 64 characters, often used by malware to obfuscate payloads or communications.</dd>
<dt>Baselining</dt><dd>The process of documenting and measuring normal system behavior over time to identify deviations that might indicate security issues.</dd>
<dt>Behavior Analytics</dt><dd>The process of collecting and analyzing user and system behavior patterns to identify potential security threats or anomalies.</dd>
<dt>Behavioral Drift</dt><dd>Gradual changes in normal behavior patterns that may complicate detection of anomalies.</dd>
<dt>Biometric Verification</dt><dd>Authentication method that uses unique biological characteristics like fingerprints or facial recognition.</dd>
<dt>BITSAdmin</dt><dd>A command-line tool for managing Background Intelligent Transfer Service (BITS), often monitored for abuse by attackers.</dd>
<dt>Blockchain</dt><dd>A distributed ledger technology that maintains a secure, decentralized record of transactions, introducing new security considerations for digital assets and smart contracts.</dd>
<dt>Border Gateway Protocol (BGP)</dt><dd>The protocol managing how packets are routed across the internet between autonomous systems.</dd>
<dt>Bring Your Own Device (BYOD)</dt><dd>A policy allowing employees to use personal devices for work, which introduces unique security challenges.</dd>
<dt>Business Continuity</dt><dd>The ability of an organization to continue operating and providing services despite disruptions or disasters.</dd>
<dt>Byte Sequence</dt><dd>An ordered set of bytes in memory or data streams, often analyzed in malware detection or forensics.</dd>
</dl>

</section>

{/* C */}
<section id="C" class="clear-section">

<h2>C</h2>

<dl class="clear-terms">
<dt>California Consumer Privacy Act (CCPA)</dt><dd>A law that regulates the collection, use, and protection of personal data in California.</dd>
<dt>Cardholder Data Environment (CDE)</dt><dd>Systems and networks that store, process, or transmit payment card data and must comply with PCI DSS requirements.</dd>
<dt>certutil.exe</dt><dd>A Windows command-line tool used for certificate management and sometimes exploited by attackers for malicious purposes.</dd>
<dt>CIA Triad</dt><dd>Core principles of information security: Confidentiality, Integrity, and Availability.</dd>
<dt>Cloud Security Posture Management (CSPM)</dt><dd>Tools and processes that continuously monitor cloud infrastructure for misconfigurations, compliance violations, and security risks.</dd>
<dt>Command and Control (C2)</dt><dd>Infrastructure used by attackers to communicate with and control compromised systems within a target network.</dd>
<dt>Command Line</dt><dd>In SOC analysis, the argument string a process was launched with. Often the load-bearing forensic field on an EDR alert because it reveals what the process was actually told to do.</dd>
<dt>Command Line Analysis</dt><dd>The examination of command-line parameters, arguments, and execution context to understand process behavior and intent.</dd>
<dt>Common Event Format (CEF)</dt><dd>A standardized log format designed to simplify event management across security devices and systems.</dd>
<dt>Common Vulnerability Scoring System (CVSS)</dt><dd>A standardized way to assess the severity of security vulnerabilities.</dd>
<dt>Compliance</dt><dd>Adherence to regulatory requirements, industry standards, and security frameworks that govern data protection and system security.</dd>
<dt>Concatenation</dt><dd>The process of combining multiple strings or commands, often used by attackers to bypass security controls or obfuscate malicious code.</dd>
<dt>Conditional Logic</dt><dd>Programming or rule-based logic that executes actions based on specific conditions or criteria.</dd>
<dt>Configuration Management</dt><dd>The process of tracking and controlling changes to systems, networks, and applications.</dd>
<dt>Configuration Management Database (CMDB)</dt><dd>Repositories that store information about IT assets and their relationships to support change and incident management.</dd>
<dt>Container Orchestration</dt><dd>Automated management, scaling, and deployment of containerized applications using platforms like Kubernetes.</dd>
<dt>Containers</dt><dd>Lightweight, standalone packages that include everything needed to run a piece of software, introducing unique security challenges in orchestration and isolation.</dd>
<dt>Containment</dt><dd>The incident-response phase between detection and eradication: isolate the affected hosts, revoke the compromised credentials, block the C2 destinations, freeze the situation so it stops getting worse while the investigation continues.</dd>
<dt>Credential</dt><dd>Whatever the system accepts as proof of identity: a password, an API key, an OAuth token, a Kerberos ticket, an NTLM hash. Credentials are the highest-value loot in most intrusions; their theft is usually the pivot point.</dd>
<dt>Critical Infrastructure</dt><dd>Essential systems, networks, or assets that are critical to an organization's operations or national security.</dd>
<dt>Cross-System</dt><dd>Interactions or communications that occur between different systems or platforms within an infrastructure.</dd>
<dt>Cybercriminals</dt><dd>Individuals or groups who use technology to commit crimes, including data theft, fraud, and system compromise for financial gain.</dd>
</dl>

</section>

{/* D */}
<section id="D" class="clear-section">

<h2>D</h2>

<dl class="clear-terms">
<dt>Data Aggregation</dt><dd>The process of collecting and combining data from multiple sources for analysis, potentially revealing security patterns or threats not visible in isolated data sets.</dd>
<dt>Data Breach</dt><dd>The unauthorized access, theft, or exposure of sensitive data.</dd>
<dt>Data Exfiltration</dt><dd>The unauthorized transfer of data from a computer or network to an external location or system.</dd>
<dt>Data Integrity</dt><dd>Ensuring data is accurate, complete, and unaltered during storage, processing, and transmission.</dd>
<dt>Data Loss Prevention (DLP)</dt><dd>A set of tools and processes that help prevent sensitive data from being lost, stolen, or compromised.</dd>
<dt>Data Protection</dt><dd>The processes and technologies used to protect sensitive data from unauthorized access, theft, or damage.</dd>
<dt>Data Retention</dt><dd>The policies and procedures that govern how long data is stored and retained.</dd>
<dt>Deception Technology</dt><dd>Security tools and techniques that deploy decoys and traps to detect, deflect, and analyze unauthorized system access attempts.</dd>
<dt>Deep Packet Inspection (DPI)</dt><dd>A technique used to inspect and analyze network traffic to detect and block malicious activity.</dd>
<dt>Detection Logic</dt><dd>The rule, model, or heuristic that decides whether a given input fires an alert. The logic that produced the alert matters as much as the alert it produced; two engines can name the same alert for very different reasons.</dd>
<dt>Detection Mechanism</dt><dd>Tools or methods employed to identify security incidents, including signature, anomaly, and behavioral detections.</dd>
<dt>Device Fingerprint</dt><dd>A unique identifier derived from hardware or software characteristics used to recognize devices.</dd>
<dt>Digital Forensics</dt><dd>The analysis and examination of digital evidence to investigate and solve crimes or security incidents.</dd>
<dt>Digital Signatures</dt><dd>Cryptographic techniques that validate the authenticity and integrity of digital messages or documents.</dd>
<dt>Disaster Recovery</dt><dd>The process of restoring systems, networks, and operations after a disaster or major disruption.</dd>
<dt>Distributed Denial-of-Service (DDoS)</dt><dd>A type of attack where multiple systems are used to flood a targeted system or network with traffic in an attempt to overwhelm it.</dd>
<dt>Distribution Pipelines</dt><dd>Processes and tools used to deploy software or updates from development to production environments.</dd>
<dt>DLL Loading</dt><dd>The process of loading Dynamic Link Libraries into a program's memory space, which can be exploited by attackers for malicious code execution.</dd>
<dt>DLL Search Order Hijacking</dt><dd>A persistence and privilege-escalation technique that places a malicious DLL where an application looks for libraries before the legitimate location, so a trusted, signed binary loads attacker code. Detected by watching for DLLs loaded from application or user-writable directories instead of their expected system paths.</dd>
<dt>Domain</dt><dd>A unique name or identifier for a system, network, or organization on the internet.</dd>
<dt>Domain Admin</dt><dd>The most powerful account class in a Windows Active Directory domain: full administrative control over every domain-joined host, every domain user, and the directory itself. Compromise of a Domain Admin account is generally treated as a domain compromise.</dd>
<dt>Domain-based Message Authentication, Reporting, and Conformance (DMARC)</dt><dd>An email validation system to prevent spoofing.</dd>
<dt>Domain Controller</dt><dd>A server that responds to security authentication requests in a Windows domain environment.</dd>
<dt>Domain Depth</dt><dd>The hierarchical level or complexity within a domain namespace or network structure.</dd>
<dt>Domain Name System (DNS)</dt><dd>A system that translates domain names into IP addresses.</dd>
<dt>Domain Name System Exfiltration</dt><dd>A technique where data is covertly sent out of a network using DNS queries.</dd>
<dt>Domain Name System Query</dt><dd>A request sent to a DNS server to resolve a domain name into an IP address.</dd>
<dt>Domain Trusts</dt><dd>Relationships established between domains to allow resource sharing and authentication.</dd>
<dt>DomainKeys Identified Mail (DKIM)</dt><dd>An email authentication method that verifies message integrity and sender identity.</dd>
<dt>Dynamic Link Library (DLL)</dt><dd>A collection of executable functions or data that can be used by multiple programs.</dd>
<dt>Dynamic Prioritization</dt><dd>Adaptive adjustment of alert or incident priority based on contextual risk factors.</dd>
</dl>

</section>

{/* E */}
<section id="E" class="clear-section">

<h2>E</h2>

<dl class="clear-terms">
<dt>Electron Framework</dt><dd>An open-source framework for building cross-platform desktop applications using web technologies.</dd>
<dt>Encoded Payloads</dt><dd>Malicious code or commands that have been transformed into a different format to avoid detection or bypass security controls.</dd>
<dt>Encryption</dt><dd>The process of converting plaintext data into unreadable ciphertext to protect it from unauthorized access.</dd>
<dt>Endpoint</dt><dd>A device that initiates network connections and runs user-facing software: laptop, desktop, server, phone, tablet. Endpoints are where most adversary tradecraft eventually shows up, which is why EDR exists.</dd>
<dt>Endpoint Detection and Response (EDR)</dt><dd>Security technology that continuously monitors and responds to threats on endpoint devices, providing advanced threat detection and incident response capabilities.</dd>
<dt>Endpoint Security</dt><dd>The processes and technologies used to protect endpoint devices from security threats.</dd>
<dt>Enterprise</dt><dd>A large organization or business that operates in multiple locations or countries.</dd>
<dt>Entitlement Matrix</dt><dd>A framework mapping user roles to their access permissions within systems.</dd>
<dt>Entity</dt><dd>A person, system, or organization that interacts with or affects a security incident.</dd>
<dt>Entropy Scoring</dt><dd>A method to measure randomness or complexity in data, often used to detect obfuscation or encryption.</dd>
<dt>Ephemeral Computing</dt><dd>A computing model where resources, such as containers or serverless functions, are temporary and exist only for the duration of a specific task or process.</dd>
<dt>Eradication</dt><dd>The phase of incident response focused on completely removing threat actors and malicious artifacts from affected systems.</dd>
<dt>Escalation Matrix</dt><dd>A predetermined framework defining when and how to elevate security incidents to higher levels of response based on severity and impact.</dd>
<dt>Evasion</dt><dd>Techniques used by attackers to avoid detection by security tools.</dd>
<dt>Event</dt><dd>An observable thing that happened: a process executed, a user logged in, a file changed, a packet was sent. Events are what produce alerts when detection logic decides they're interesting. Most events are not alerts; most alerts are events.</dd>
<dt>Event Context</dt><dd>The circumstances and environment surrounding a security event.</dd>
<dt>Event Correlation</dt><dd>The process of analyzing multiple events across different sources to identify relationships and determine if they are part of a larger security incident.</dd>
<dt>Event Triage</dt><dd>The phase that sits between detection and incident response: deciding whether an alert is real, whom it concerns, what its blast radius might be, and whether it crosses an escalation threshold. The ASSURED methodology is a structured way to do triage.</dd>
<dt>Excessive Permissions</dt><dd>User or process privileges beyond what is necessary for their role, increasing security risk.</dd>
<dt>Exfiltration</dt><dd>The unauthorized transfer of data from a system or network, often as part of a data breach or espionage operation.</dd>
<dt>Exploit</dt><dd>A technique or piece of code that turns a vulnerability into actual capability: remote code execution, privilege escalation, authentication bypass. A vulnerability without an exploit is theoretical; a vulnerability with one is operational.</dd>
</dl>

</section>

{/* F */}
<section id="F" class="clear-section">

<h2>F</h2>

<dl class="clear-terms">
<dt>False Positive</dt><dd>A security alert that fires on activity that is, on inspection, benign. The detection logic matched a pattern that looked malicious but was not. Distinct from a <em>benign true positive</em>, which is real adversary-like activity that does not warrant action in the local context.</dd>
<dt>False-Premise</dt><dd>An incorrect assumption or conclusion about a security event that leads to improper investigation or response.</dd>
<dt>Federation</dt><dd>A system allowing users to access multiple independent systems using a single set of credentials.</dd>
<dt>Feedback Loop</dt><dd>A process where information from outcomes is used to improve future detection or response.</dd>
<dt>FIDO2</dt><dd>An authentication standard enabling passwordless login using biometrics or security keys.</dd>
<dt>File Integrity Monitoring (FIM)</dt><dd>A security control that detects unauthorized changes to files or configurations.</dd>
<dt>Firewall</dt><dd>A network security system that controls and monitors incoming and outgoing traffic based on predetermined security rules.</dd>
<dt>Forensics</dt><dd>The application of scientific methods to collect, preserve, and analyze digital evidence for security investigations and incident response.</dd>
<dt>Framework</dt><dd>A structured approach or set of guidelines used to build security programs or processes.</dd>
<dt>Fully Qualified Domain Name (FQDN)</dt><dd>The complete domain name specifying its exact location in the DNS hierarchy.</dd>
</dl>

</section>

<dl class="clear-terms">
<dt>General Data Protection Regulation (GDPR)</dt><dd>European Union regulation establishing requirements for processing and protecting personal data, with specific security and breach notification requirements.</dd>
<dt>Geolocation</dt><dd>The process of determining the physical location of a device or IP address.</dd>
</dl>

</section>

<section id="H" class="clear-section">

<h2>H</h2>

<dl class="clear-terms">
<dt>Hashes</dt><dd>Cryptographic functions that generate fixed-size values representing digital data, used for file integrity verification and malware identification.</dd>
<dt>Health Insurance Portability and Accountability Act (HIPAA)</dt><dd>U.S. legislation that sets standards for protecting sensitive patient health information, including specific security and privacy requirements.</dd>
<dt>Heuristic Detection</dt><dd>A detection method that uses rules and patterns to identify potentially malicious behavior based on common characteristics of malware or attacks.</dd>
<dt>Honeypot</dt><dd>A decoy system designed to lure attackers and study their tactics.</dd>
<dt>HTA Content</dt><dd>HTML Application files that can execute scripts, sometimes abused for malicious purposes.</dd>
<dt>Hybrid Infrastructure</dt><dd>Computing environment that combines on-premises, private cloud, and public cloud services.</dd>
<dt>Hypertext Transfer Protocol (HTTP)</dt><dd>The foundation protocol for data communication on the web.</dd>
<dt>Hypertext Transfer Protocol Secure (HTTPS)</dt><dd>Secure version of HTTP using encryption to protect data in transit.</dd>
</dl>

</section>

{/* I */}
<section id="I" class="clear-section">

<h2>I</h2>

<dl class="clear-terms">
<dt>Impact</dt><dd>The potential effect or damage caused by a security incident.</dd>
<dt>Incident</dt><dd>A confirmed compromise of confidentiality, integrity, or availability: an alert (or series of alerts) that triage has validated as real adversary activity, warranting an IR response. An event becomes an incident at the verdict, not at the alert.</dd>
<dt>Incident Command</dt><dd>A structured leadership model used to manage complex security incidents.</dd>
<dt>Incident Response</dt><dd>The organized approach to addressing and managing the aftermath of a security breach or cyberattack, including preparation, detection, analysis, containment, eradication, and recovery.</dd>
<dt>Indicators of Compromise (IoC)</dt><dd>Atomic, replayable artifacts that, when observed, suggest an intrusion has occurred or is in progress: file hashes, IPs, domains, registry keys, certificate fingerprints, and similar discrete observables. Behavioral patterns (process trees, sequence of actions) are not IoCs; they live one layer up as TTPs.</dd>
<dt>Information Security</dt><dd>The practices and technologies used to protect information and data from unauthorized access, use, disclosure, disruption, modification, or destruction.</dd>
<dt>Information Sharing and Analysis Centers (ISACs)</dt><dd>Industry groups that share cyber threat information.</dd>
<dt>Information Technology Service Management (ITSM)</dt><dd>Frameworks and tools to manage IT services and processes.</dd>
<dt>Infrastructure</dt><dd>The underlying systems, networks, and architecture that support an organization's operations.</dd>
<dt>Insider Risk</dt><dd>The potential for harm from individuals with legitimate access arising from mistakes, policy violations, or unsafe habits, not from intent. Distinct from <em>insider threat</em>, which is deliberate.</dd>
<dt>Insider Threat</dt><dd>A person with authorized access who deliberately misuses it to harm the organization through theft, sabotage, or assisting external attackers. Distinct from insider risk, which also covers unintentional harm from negligence or mistakes.</dd>
<dt>Insider Threat Matrix</dt><dd>A public framework maintained at insiderthreatmatrix.org that catalogs insider techniques across motive, means, preparation, infringement, and anti-forensics. Useful as a shared vocabulary for describing insider risk and threat.</dd>
<dt>Integrated Development Environment (IDE)</dt><dd>Software that provides comprehensive facilities to programmers.</dd>
<dt>Intelligence</dt><dd>Information gathered and analyzed to understand and predict potential security threats.</dd>
<dt>IntelliSense</dt><dd>A code-completion aid commonly found in development environments.</dd>
<dt>Inter-Process Communication</dt><dd>Mechanisms that allow different processes to communicate within an operating system.</dd>
<dt>Internet of Things (IoT)</dt><dd>Network of physical devices embedded with sensors, software, and connectivity, introducing new security challenges due to their often limited security capabilities.</dd>
<dt>Internet Protocol (IP) Address</dt><dd>A unique address assigned to a device or system on a network.</dd>
<dt>Intrusion Detection System (IDS)</dt><dd>Security system that monitors network traffic for suspicious activity and policy violations, generating alerts for potential security incidents.</dd>
<dt>Intrusion Prevention System (IPS)</dt><dd>Security system that not only detects but actively blocks or prevents identified suspicious activity and policy violations.</dd>
<dt>Isolated Execution Environment</dt><dd>A secure area where code runs isolated from other system components to prevent interference.</dd>
<dt>Isolation Forests</dt><dd>A machine learning algorithm used for anomaly detection by isolating anomalies in data.</dd>
</dl>

</section>

{/* J */}
<section id="J" class="clear-section">

<h2>J</h2>

<dl class="clear-terms">
<dt>JA3</dt><dd>A method for fingerprinting TLS client applications by hashing specific fields in the TLS Client Hello packet. Degraded against modern clients: Chrome's extension-order randomization (2023) and GREASE values fragment a single client into many hashes.</dd>
<dt>JA3S</dt><dd>The server-side counterpart to JA3, it fingerprints TLS servers by hashing fields in the Server Hello packet.</dd>
<dt>JA4</dt><dd>The 2023 successor to JA3 from FoxIO. A modernized TLS-client fingerprint that sorts extensions before hashing (defeating randomization), handles TLS 1.3, and covers QUIC natively via a leading "q" or "t" transport marker. Part of the JA4+ suite, which adds separate fingerprints such as JA4H (HTTP client) and JA4S (TLS server).</dd>
</dl>

</section>

{/* K */}
<section id="K" class="clear-section">

<h2>K</h2>

<dl class="clear-terms">
<dt>Kerberoasting</dt><dd>Requesting Kerberos service tickets (TGS) for accounts with Service Principal Names (SPNs) and cracking them offline. With the legacy RC4 encryption type the ticket is encrypted using a key equal to the service account's NTLM hash, so a weak service-account password becomes a crackable ciphertext (AES-only accounts crack far more slowly), and any user who can authenticate to the domain can request the ticket.</dd>
<dt>Kerberos</dt><dd>A network authentication protocol using tickets to allow secure identity verification.</dd>
<dt>Kubernetes</dt><dd>An open-source system for automating deployment, scaling, and management of containerized applications.</dd>
</dl>

</section>

{/* L */}
<section id="L" class="clear-section">

<h2>L</h2>

      totalVisible += visibleInSection;
      sec.style.display = visibleInSection > 0 ? '' : 'none';
      if (visibleInSection > 0) anyVisible = true;
    });
    if (empty) empty.hidden = anyVisible || query === '';
    if (resultsCount) {
      resultsCount.textContent = query === ''
        ? ''
        : totalVisible + (totalVisible === 1 ? ' term matches' : ' terms match');
    }
  };

  if (search) {
    _reg(search, 'input', () => filterTerms(search.value));
    _reg(search, 'keydown', (e) => { if (e.key === 'Escape') { search.value = ''; filterTerms(''); search.blur(); } });
  }

  // SC 2.1.4: single-key shortcuts and typed eggs honor the site-wide
  // easter-egg kill switch (the toggle lives in the docs layout footer and
  // persists in localStorage).
  const eggsEnabled = () => {
    try { return localStorage.getItem('assured-eggs') !== 'off'; } catch (e) { return true; }
  };

  // Keyboard shortcuts: "/" focuses search, "?" rolls spotlight
  _reg(document, 'keydown', (e) => {
    if (!eggsEnabled()) return;
    const tag = (e.target && e.target.tagName) || '';
    const editable = tag === 'INPUT' || tag === 'TEXTAREA' || (e.target && e.target.isContentEditable);
    if (e.key === '/' && !editable) {
      e.preventDefault();
      if (search) search.focus();
    } else if (e.key === '?' && !editable) {
      e.preventDefault();
      pickSpotlight();
    }
  });

  // Easter egg: type "clearmymind" → everything goes greyscale briefly
  let typed = '';
  _reg(document, 'keydown', (e) => {
    if (!eggsEnabled()) return;
    if (e.key && e.key.length === 1) {
      typed = (typed + e.key.toLowerCase()).slice(-14);
      if (typed.endsWith('clearmymind')) {
        typed = '';
        page.classList.add('clear-zen');
        const t = document.createElement('div');
        t.className = 'clear-toast';
        t.textContent = '🧘 zen mode, clarity engaged for 5 seconds';
        page.appendChild(t);
        setTimeout(() => t.classList.add('is-out'), 4400);
        setTimeout(() => { t.remove(); page.classList.remove('clear-zen'); }, 5000);
      }
    }
  });
})();
`}</script>
