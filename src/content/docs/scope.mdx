# S: Scope - Defining Investigation Boundaries

The Scope phase is the third component of the ASSURED methodology, focusing on establishing clear investigation boundaries and parameters to focus investigative efforts effectively. This phase ensures that analysts have a well-defined framework for their investigation, preventing scope creep while ensuring comprehensive coverage of the security event.

## Overview

Scope definition is critical for effective security investigations as it:
- Establishes clear boundaries for the investigation
- Ensures appropriate resource allocation
- Defines regulatory and compliance requirements
- Sets expectations for stakeholders
- Provides a framework for decision-making

## Regulatory Requirements

Understanding and incorporating regulatory requirements is essential for proper scope definition. Different regulations may apply depending on the type of data involved, the industry, and the geographic location of the organization.

### Common Regulatory Frameworks

**GDPR (General Data Protection Regulation)**
- 72-hour breach notification requirement
- Data protection impact assessments
- Documentation of processing activities
- Right to be informed requirements

**HIPAA (Health Insurance Portability and Accountability Act)**
- Breach notification within 60 days
- Risk assessment requirements
- Documentation of security incidents
- Business associate agreements

**PCI DSS (Payment Card Industry Data Security Standard)**
- Incident response procedures
- Forensic investigation requirements
- Compensating controls documentation
- Quarterly security assessments

**SOX (Sarbanes-Oxley Act)**
- Internal control documentation
- Management assessment requirements
- Audit trail maintenance
- Disclosure controls and procedures

### Compliance Considerations

**Data Classification**
- Identify the sensitivity level of affected data
- Determine applicable regulatory requirements
- Assess notification obligations
- Plan for audit and compliance reporting

**Geographic Considerations**
- Identify affected jurisdictions
- Understand local data protection laws
- Plan for cross-border data transfer issues
- Coordinate with local legal counsel

**Industry-Specific Requirements**
- Financial services regulations
- Healthcare compliance requirements
- Government contractor obligations
- Critical infrastructure protections

## Time-Based Parameters

Establishing appropriate time-based parameters is crucial for effective investigation scope. These parameters define the investigation window and help prioritize activities.

### Investigation Timeframes

**Initial Response Window**
- First 24 hours: Immediate containment and assessment
- First 72 hours: Detailed investigation and evidence collection
- First week: Comprehensive analysis and reporting
- First month: Follow-up actions and lessons learned

**Evidence Collection Windows**
- Log retention periods
- Backup availability windows
- Network monitoring data retention
- Endpoint data collection timelines

**Regulatory Notification Deadlines**
- GDPR: 72 hours for supervisory authority notification
- HIPAA: 60 days for affected individuals
- State breach notification laws: Varies by jurisdiction
- Industry-specific requirements

### Timeline Considerations

**Business Impact Assessment**
- Critical business functions affected
- Customer impact evaluation
- Financial loss estimation
- Reputational risk assessment

**Resource Availability**
- Analyst availability and expertise
- Tool access and licensing
- External vendor support
- Management oversight requirements

**Evidence Degradation**
- Volatile data collection priorities
- Network log retention limits
- Endpoint data availability
- Third-party data access windows

## Entity-Based Scopes

Defining which entities are within the investigation scope is essential for focused and efficient investigations.

### System Entities

**Affected Systems**
- Primary systems involved in the incident
- Connected or related systems
- Backup and recovery systems
- Monitoring and logging systems

**Network Infrastructure**
- Network segments involved
- Firewall and security devices
- DNS and routing infrastructure
- Wireless networks and access points

**Cloud Resources**
- Cloud service providers involved
- Virtual machines and containers
- Storage and database systems
- API endpoints and services

### User Entities

**Directly Affected Users**
- Users whose accounts were compromised
- Users who reported the incident
- Users with access to affected systems
- Administrative and privileged accounts

**Indirectly Affected Users**
- Users in the same organizational unit
- Users with similar access privileges
- Users who may have been targeted
- External users and partners

### Data Entities

**Data Types in Scope**
- Personal identifiable information (PII)
- Protected health information (PHI)
- Financial and payment data
- Intellectual property and trade secrets

**Data Locations**
- Primary data storage systems
- Backup and archive systems
- Cloud storage services
- Third-party data processors

**Data Access Patterns**
- Normal access patterns
- Unusual or suspicious access
- Data exfiltration indicators
- Data modification or deletion

## Working Example: Initial Scope Definition

### Scenario: Suspicious PowerShell Execution

**Initial Alert Context:**
- User: jsmith@company.com (System Administrator)
- System: Workstation-IT-047 (Windows 10)
- Time: 14:30 UTC (Business hours)
- Detection: EDR behavioral analytics

**Scope Definition:**

**Regulatory Requirements:**
- No PII or PHI involved
- Standard incident response procedures apply
- Internal documentation requirements
- No external notification required

**Time-Based Parameters:**
- Investigation window: 48 hours
- Evidence collection: Immediate
- Reporting deadline: 24 hours
- Follow-up actions: 1 week

**Entity-Based Scope:**
- Primary: Workstation-IT-047
- Secondary: Domain controller, file servers
- Users: jsmith@company.com, IT team members
- Data: System logs, PowerShell execution logs

**Tool Integration:**
- EDR platform for endpoint analysis
- SIEM for log correlation
- Active Directory for user analysis
- Network monitoring for traffic analysis

**Investigation Boundaries:**
- Focus on PowerShell execution analysis
- User behavior assessment
- System integrity verification
- No broader network sweep required

## Scope Refinement Process

### Dynamic Scope Adjustment

**New Information Integration**
- Additional alerts or indicators
- Expanded threat intelligence
- New evidence discovery
- Stakeholder input and requirements

**Scope Expansion Criteria**
- Evidence of lateral movement
- Additional affected systems
- Broader attack campaign indicators
- Regulatory requirement changes

**Scope Reduction Criteria**
- False positive confirmation
- Limited impact assessment
- Resource constraint considerations
- Management direction

### Documentation Requirements

**Scope Documentation**
- Initial scope definition
- Scope changes and rationale
- Stakeholder approvals
- Resource allocation decisions

**Change Management**
- Scope change requests
- Approval processes
- Communication protocols
- Documentation updates

## Transition to Uncover Phase

After completing the Scope definition, the investigation transitions to the **Uncover** phase, where analysts will:

- Begin systematic evidence collection
- Apply the defined scope parameters
- Use identified tools and systems
- Follow established timelines and boundaries

The comprehensive scope definition provides the framework for effective investigation execution in the Uncover phase.

## Key Takeaways

1. **Clear Boundaries**: Well-defined scope prevents investigation drift and ensures focus
2. **Regulatory Compliance**: Understanding requirements ensures proper investigation approach
3. **Resource Planning**: Appropriate scope definition enables effective resource allocation
4. **Stakeholder Alignment**: Clear scope ensures all parties understand investigation parameters
5. **Flexibility**: Scope should be adaptable as new information emerges

The Scope phase provides the essential framework for focused, efficient, and compliant security investigations within the ASSURED methodology.
