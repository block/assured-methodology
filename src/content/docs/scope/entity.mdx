# Primary vs. secondary

<div class="entity-bounds">
  <div class="entity-bound entity-bound--primary">
    <span class="entity-bound__tag">Primary</span>
    <p>Entities directly involved in the alert. The user whose account fired the alert, the host that produced the telemetry, the service account that authenticated the action. Primary entities get full investigation depth: every dimension, every available data source, full historical window.</p>
  </div>
  <div class="entity-bound entity-bound--secondary">
    <span class="entity-bound__tag">Secondary</span>
    <p>Entities connected to the primary set but not directly in the alert. The peer accounts that share a trust path, the systems the primary entities have access to, the parent service that issued the credentials. Secondary entities get baseline-comparison depth: are they behaving normally? Investigated more thoroughly only if a primary investigation surfaces them.</p>
  </div>
</div>

---

# Three modeling techniques

<div class="techniques-grid">
  <div class="technique-card">
    <h4>🗺️ Relationship mapping</h4>
    <p>Diagram which entities are connected to which. Trust paths, authentication chains, communication patterns. The map shows where lateral movement could go and where the investigation needs to look.</p>
  </div>
  <div class="technique-card">
    <h4>🔑 Access modeling</h4>
    <p>Which entities can access which systems and data. Built from identity provider data and asset inventories. A compromised entity's access model is the immediate-blast-radius estimate.</p>
  </div>
  <div class="technique-card">
    <h4>🔗 Dependency tracing</h4>
    <p>Which downstream services depend on which entities. If an account is compromised, what other systems would be affected by responding to that compromise? (Disabling a service account that production depends on is its own incident.)</p>
  </div>
</div>

<Callout variant="info" title="Containment has its own scope">
Entity scope informs containment decisions. Isolating a host or disabling an account can have downstream effects. Scoping the secondary entities means understanding what depends on each primary entity, so containment does not break business operations as collateral.
</Callout>

<KeyTakeaway>
Entity scope is the difference between "investigate the user" and "investigate the user, the three accounts that authenticate as them, and the four systems those credentials access." The second is far more useful, and Scope is the phase that draws the line.
</KeyTakeaway>
