<ChapterExample
  title="Drawing the lines around the finance-team intrusion"
  scenario="Subject handed Scope a map of five identities plus a downstream payment workflow. Scope's job is to turn that map into a formal investigation boundary."
>

<ExampleStepper steps={["Regulatory check", "Time window", "Entity boundaries", "Infrastructure check", "Hand off to Uncover"]}>

  <div data-step class="example-step">
    <h3>Step 1. Regulatory check</h3>
    <p>The compromised user dlin has read access to a cloud finance platform that processes payment data. That triggers PCI DSS implications. The platform also stores personally identifiable information for vendors, which brings GDPR into scope for any EU-resident vendor records.</p>
    <p><strong>Decisions:</strong> Document PCI exposure now. Engage compliance early so any breach-notification clock can run in parallel with the technical investigation. Tag the case as both PCI and GDPR relevant.</p>
  </div>

  <div data-step class="example-step">
    <h3>Step 2. Time window</h3>
    <p>The alert is a phishing-driven intrusion that fired today. The Subject phase did not find slow-burn signals. The default window for this threat type is 24 to 72 hours of historical review, with a 4-week look at the primary entities to confirm no prior staging.</p>
    <p><strong>Decisions:</strong> Set primary window at 72 hours pre-alert through current time. Set extended check at 4 weeks for dlin's account specifically. Note that endpoint telemetry has 90-day retention, identity telemetry has 1 year — both are sufficient.</p>
  </div>

  <div data-step class="example-step">
    <h3>Step 3. Entity boundaries</h3>
    <p>Subject's entity map gets categorized:</p>
    <ul class="example-step__list">
      <li><strong>Primary:</strong> dlin (user), laptop-finance-09 (host), dlin's cloud identity.</li>
      <li><strong>Secondary:</strong> The service account dlin authenticates against. The two other finance users who opened the same email. The external sender.</li>
      <li><strong>Out of scope (for now):</strong> Other finance team members who received but did not open the email. Their inboxes still get a baseline check, but no full investigation unless something new surfaces.</li>
    </ul>
    <p><strong>Decisions:</strong> Primary entities get full investigation depth. Secondary entities get baseline comparison and are upgraded only on a signal.</p>
  </div>

  <div data-step class="example-step">
    <h3>Step 4. Infrastructure check</h3>
    <p>What can the SOC see for this case?</p>
    <ul class="example-step__list">
      <li><strong>In scope:</strong> EDR on the laptop, cloud identity logs, firewall logs, proxy logs, mailbox audit.</li>
      <li><strong>Limited:</strong> The cloud finance platform's in-app activity is in the vendor's logs; the SOC sees authentication and gross API calls only. A vendor request is needed for deeper investigation.</li>
      <li><strong>Gaps:</strong> If the user worked from a personal phone via the cloud platform's mobile app, that activity may not show up in corporate telemetry.</li>
    </ul>
    <p><strong>Decisions:</strong> Note the cloud-platform gap explicitly. If Uncover needs deeper data, request from the vendor now so it arrives in parallel.</p>
  </div>

  <div data-step class="example-step">
    <h3>Step 5. Hand off to Uncover</h3>
    <p>The Scope deliverable is a one-page boundary statement Uncover can pin above their query window:</p>
    <ul class="example-step__list">
      <li><strong>Threat type:</strong> phishing-driven intrusion.</li>
      <li><strong>Time:</strong> 72 hours primary, 4 weeks extended for dlin.</li>
      <li><strong>Primary entities:</strong> dlin, laptop-finance-09, cloud identity. Full depth.</li>
      <li><strong>Secondary entities:</strong> service account, 2 other finance users, external sender. Baseline depth.</li>
      <li><strong>Regulatory:</strong> PCI and GDPR triggers active. Compliance engaged.</li>
      <li><strong>Infrastructure gaps:</strong> mobile app activity on the cloud platform may be invisible; vendor request submitted.</li>
    </ul>
  </div>

</ExampleStepper>

</ChapterExample>

<KeyTakeaway>
Scope turned an entity map into a defensible investigation boundary. Uncover now knows what to look for, where, when, and what falls outside the bounds. Without scope, the same investigation would have wandered for hours.
</KeyTakeaway>
