  <QuizItem
    prompt="Alert and Subject both lean false-positive on a developer-workstation alert, but the user's account can reach a dozen other systems. How does Scope draw the boundary?"
    options={[
      { value: "broad", label: "Wide: add every reachable system as a secondary entity. Broad scope is cheap insurance while the verdict is not final." },
      { value: "narrow", label: "Narrow: the user, the workstation, the flagged binary. Reachable-but-unevidenced systems stay out, with the expansion path documented." },
      { value: "sample", label: "Split the difference: add the three most sensitive reachable systems as secondaries." },
      { value: "skip", label: "Skip the boundary: a probable false-positive does not need formal scoping." },
    ]}
    answer="narrow"
    explanation="This is restraint scoping, and it is as much a Scope skill as expansion. Access alone is topology, not evidence, and every entity added spends Uncover's depth where there is no signal. The narrow boundary is defensible precisely because the expansion path exists: if Uncover surfaces evidence touching another system, the decision tree grows the boundary with a documented justification. Sprawl on a false-positive-leaning case is how a fast close becomes a five-hour one."
  />

  <QuizItem
    prompt="A hospital SOC confirms a compromised workstation had access to systems holding PHI. When does HIPAA's 60-day individual-notification clock start?"
    options={[
      { value: "confirmed", label: "When the technical investigation confirms PHI actually left the covered environment." },
      { value: "discovery", label: "At discovery: when the workforce knew or reasonably should have known. Maybe the alert." },
      { value: "case-open", label: "When the privacy officer formally opens a breach case in the compliance system." },
      { value: "assessment", label: "When counsel signs off on the four-factor risk assessment that a breach occurred." },
    ]}
    answer="discovery"
    explanation="The 60-day clock (45 CFR §164.404) runs from discovery, not from confirmation; discovery is a knew-or-should-have-known standard applied to the whole workforce. The alert that starts triage can be the discovery event, which is why Scope commits the timestamp and engages the privacy officer early. The four-factor assessment (§164.402) decides whether notification is required at all; it does not pause the clock."
  />

  <QuizItem
    prompt="During Scope, the analyst confirms that a compromised account assumed a cloud role during the investigation window. The decision-tree response is..."
    options={[
      { value: "ignore", label: "Note it but stay focused on the originating endpoint until Uncover produces evidence." },
      { value: "add-role", label: "Add the role and its reachable resources into scope; review AssumeRole patterns vs. normal." },
      { value: "isolate", label: "Immediately isolate every system the role can access before the session can be used again." },
      { value: "wait", label: "Keep scope as-is until Uncover finds evidence of misuse; expansion without evidence is churn." },
    ]}
    answer="add-role"
    explanation="The IF/THEN decision-tree pattern is Scope's structured way of evolving the boundary. A cloud-role assumption is evidence; the methodology says incorporate it now and document the three-line justification (evidence, risk, required actions) so the expansion is defensible. Waiting for Uncover to surface it would mean Uncover queries outside its own scope to find what Scope should have already framed."
  />

  <QuizItem
    prompt="Scope confirms a compromised identity can reach systems inside the cardholder data environment (CDE). What does the methodology require?"
    options={[
      { value: "recognize", label: "Tag the case PCI-relevant, preserve CDE audit logs, notify the acquirer-relationship owner." },
      { value: "full-access", label: "Request full CDE access for the analyst so cardholder-data exposure can be sampled directly." },
      { value: "wait", label: "Wait for confirmed cardholder-data exfiltration before involving compliance or the acquirer." },
      { value: "isolate", label: "Isolate every CDE system immediately; PCI requires containment within one hour." },
    ]}
    answer="recognize"
    explanation="PCI DSS is contractual: card-brand rules require prompt notification of suspected account-data compromise through the acquirer, and a PFI may later re-examine everything preserved in the first hours. A compliant environment guarantees 12 months of audit logs with 3 months immediately available (Req. 10.5.1), but stopping rotation is still the analyst's job. And investigative access into the CDE follows the same least-privilege controls as any other access: defaulting to full access is exactly backwards."
  />

  <QuizItem
    prompt="A US SOC investigates a compromised account belonging to an employee in Germany, with the relevant logs stored in an EU region. What does Scope's sovereignty boundary require?"
    options={[
      { value: "move", label: "Copy the EU logs into the US SIEM. Centralized analysis beats jurisdictional caution during an active case." },
      { value: "inregion", label: "Check residency constraints before moving data; the investigation may need to run in-region or through a regional team." },
      { value: "legal-later", label: "Proceed normally. Sovereignty is a legal-team concern that begins after triage closes." },
      { value: "anonymize", label: "Strip usernames from the logs before transfer; anonymized data is exempt from residency rules." },
    ]}
    answer="inregion"
    explanation="Data-residency rules can prevent moving log data across regions, and employee-privacy regimes can restrict what is examined at all. Scope is where that constraint is recognized, because discovering it mid-Uncover means evidence already moved where it should not have. The pseudonymization distractor fails for a reason worth knowing: data that can be re-linked to a person generally remains personal data under GDPR, so stripping usernames does not lift the constraint."
  />
