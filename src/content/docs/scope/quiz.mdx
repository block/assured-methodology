  <QuizItem

    options={[

    ]}
    answer="24-72"
    explanation="Phishing-driven intrusion typically progresses within days, but ruling out earlier staging requires a longer look on the primary entities. The two-window pattern (short primary + extended look on primaries) is a common Scope decision for this threat type."

  <QuizItem
    prompt="The Subject phase identified seven identities connected to the alert. How many should be primary in scope?"
    options={[
      { value: "all", label: "All seven. Investigate each fully." },
      { value: "depends", label: "It depends on which identities were directly involved in the alert vs. connected by trust paths. Primary entities get full depth; secondary entities get baseline comparison and are upgraded only on a signal." },
      { value: "one", label: "One. The first one named in the alert." },
      { value: "three", label: "Three. That is the manageable number." },
    ]}
    answer="depends"
    explanation="Primary entities are those directly involved in the alert. Secondary entities are connected but not in the alert. The split keeps investigation depth proportional to evidence rather than spending equal time on every identity in the map."
  />

  <QuizItem
    prompt="An investigation needs in-app activity from a SaaS platform, but the SOC only has authentication logs and gross API metrics. What does Scope require?"
    options={[
      { value: "ignore", label: "Ignore the gap. Make do with what is available." },
      { value: "document", label: "Name the gap explicitly in the Scope output. Submit a vendor data request now so it can arrive in parallel with the rest of the investigation." },
      { value: "stop", label: "Stop the investigation until the gap is closed." },
      { value: "guess", label: "Reconstruct the in-app activity from authentication patterns alone." },
    ]}
    answer="document"
    explanation="Naming what cannot be seen is part of Scope. It prevents wasted effort on impossible queries, and it lets the analyst submit vendor or external-team requests early so the data arrives in parallel."
  />

  <QuizItem
    prompt="A hospital SOC confirms a compromised workstation had access to systems holding PHI. When does HIPAA's 60-day individual-notification clock start?"
    options={[
      { value: "confirmed", label: "When the technical investigation confirms PHI was actually exfiltrated." },
      { value: "discovery", label: "At discovery: the first day anyone in the workforce (other than the person responsible) knew, or with reasonable diligence should have known, of the potential breach. That can be the alert itself." },
      { value: "case-open", label: "When the privacy officer formally opens a breach case." },
      { value: "assessment", label: "When counsel signs off on the four-factor risk assessment." },
    ]}
    answer="discovery"
    explanation="The 60-day clock (45 CFR §164.404) runs from discovery, not from confirmation — and discovery is a knew-or-should-have-known standard applied to the whole workforce. The alert that starts triage can be the discovery event, which is why Scope commits the timestamp and engages the privacy officer early. The four-factor assessment (§164.402) decides whether notification is required at all; it does not pause the clock."
  />

  <QuizItem
    prompt="During Scope, the analyst confirms that a compromised account assumed a cloud role during the investigation window. The decision-tree response is..."
    options={[
      { value: "ignore", label: "Note it but stay focused on the originating endpoint." },
      { value: "add-role", label: "Add the cloud role and resources it can touch into scope. Review STS AssumeRole patterns against normal usage. Document the evidence, risk, and required actions." },
      { value: "isolate", label: "Immediately isolate every system the role can access." },
      { value: "wait", label: "Wait for Uncover to find evidence of misuse before expanding scope." },
    ]}
    answer="add-role"
    explanation="The IF/THEN decision-tree pattern is Scope's structured way of evolving the boundary. A cloud-role assumption is evidence; the methodology says incorporate it now and document the three-line justification (evidence, risk, required actions) so the expansion is defensible. Waiting for Uncover to surface it would mean Uncover queries outside its own scope to find what Scope should have already framed."
  />

  <QuizItem
    prompt="Scope confirms a compromised identity can reach systems inside the cardholder data environment (CDE). What does the methodology require?"
    options={[
      { value: "recognize", label: "Tag the case PCI-relevant, preserve CDE audit logs beyond their rotation schedule, and notify the owner of the acquirer relationship — in parallel with the technical investigation." },
      { value: "full-access", label: "Request full CDE access for the analyst so cardholder data can be sampled directly." },
      { value: "wait", label: "Wait for confirmed cardholder-data exfiltration before involving compliance." },
      { value: "isolate", label: "Isolate every CDE system immediately; PCI requires containment within one hour." },
    ]}
    answer="recognize"
    explanation="PCI DSS is contractual: card-brand rules require prompt notification of suspected account-data compromise through the acquirer, and a PFI may later re-examine everything preserved in the first hours. A compliant environment guarantees 12 months of audit logs with 3 months immediately available (Req. 10.5.1), but stopping rotation is still the analyst's job. And investigative access into the CDE follows the same least-privilege controls as any other access — defaulting to full access is exactly backwards."
  />

  <QuizItem
    prompt="The Scope handoff to Uncover should include investigative questions. Why?"
    options={[
      { value: "format", label: "Standard format. Required for documentation." },
      { value: "focus", label: "To focus Uncover on the most critical unknowns instead of broad data exploration. Specific questions drive specific queries; broad ones drive wandering." },
      { value: "audit", label: "For audit purposes only." },
      { value: "duplicate", label: "Because Uncover does not have access to Subject's findings." },
    ]}
    answer="focus"
    explanation="Uncover's depth comes from working through specific investigative questions. How did the attacker get in? What systems were touched? Was data moved? Is persistence active? Scope frames those questions before the data is pulled, which is what keeps Uncover from running broad queries and hoping. The questions are how the methodology converts a boundary into actionable analytical effort."
    hint="Think about what makes the difference between focused triage and unstructured exploration."
  />
