# What Scope hands forward

A Scope deliverable answers four questions Uncover needs to know before opening a query window:

<div class="handoff">
  <div class="handoff-row">
    <h4>What threat type are we investigating?</h4>
    <p>Determines which playbooks Uncover should reach for and which sources are most relevant.</p>
  </div>
  <div class="handoff-row">
    <h4>What time window applies, and to which entities?</h4>
    <p>Primary entities may get one window, secondary entities another, extended-look entities a third. Uncover queries reference these windows directly.</p>
  </div>
  <div class="handoff-row">
    <h4>Which entities are in scope, at what depth?</h4>
    <p>Full depth for primary, baseline comparison for secondary. Out-of-scope entities are documented and not investigated unless something new surfaces.</p>
  </div>
  <div class="handoff-row">
    <h4>What regulatory and infrastructure constraints apply?</h4>
    <p>Regulatory triggers active. Infrastructure gaps documented. Vendor requests in flight if needed.</p>
  </div>
</div>

<Callout variant="info" title="The Scope output is a one-page document">
A good Scope deliverable fits on a page. Threat type, time windows, entity lists, constraints. Any analyst joining mid-investigation should be able to read that page and know what is in and out without asking.
</Callout>

<KeyTakeaway>
Scope is invisible when it works. Uncover stays on the rails, the investigation finishes on time, and the case ends with a complete, defensible record. Scope skipped is hours of wandering.
</KeyTakeaway>
