# Four working pieces

<div class="framework-grid">
  <div class="framework-card">
    <span class="framework-card__num">01</span>
    <h3>🔍 Pattern recognition</h3>
    <p>Learning the shapes of normal and not-normal for each entity type. Mostly built from experience, but documented well it becomes a teachable skill.</p>
  </div>
  <div class="framework-card">
    <span class="framework-card__num">02</span>
    <h3>📈 Baseline development</h3>
    <p>What this entity normally does. Statistical models, ML profiles, or hand-curated rules. The baseline is the reference the analyst compares against.</p>
  </div>
  <div class="framework-card">
    <span class="framework-card__num">03</span>
    <h3>⚠️ Anomaly detection</h3>
    <p>Surface deviations from the baseline. Single-event or sequential. Confidence depends on how stable the baseline is and how cleanly the deviation falls outside it.</p>
  </div>
  <div class="framework-card">
    <span class="framework-card__num">04</span>
    <h3>🎯 Subject-centric triage</h3>
    <p>Apply the framework with the entity in the foreground. Not "is this unusual in the environment" but "is this unusual for <em>this</em> entity."</p>
  </div>
</div>

# Building good baselines

A baseline is only as useful as the data feeding it. The framework asks three questions of every baseline.

<div class="baseline-questions">
  <div class="baseline-question">
    <h4>What window is the baseline built over?</h4>
    <p>Too short and seasonal patterns get missed (a finance close at end-of-month, holiday slowdowns). Too long and stale behavior dilutes the signal. Typical starting point: rolling 30 to 90 days, with explicit handling for seasonal events.</p>
  </div>
  <div class="baseline-question">
    <h4>How is the entity grouped?</h4>
    <p>An individual entity baseline catches deviations from <em>its</em> history. A peer-group baseline (other entities in the same role) catches drift across the role. Both have value; both deserve their own thresholds.</p>
  </div>
  <div class="baseline-question">
    <h4>What enrichment feeds the baseline?</h4>
    <p>HR data for role context. Business calendars for legitimate off-hours. Change management tickets for planned activity. A baseline without context generates noise that looks like anomaly but is just business.</p>
  </div>
</div>

# Subject-centric triage in practice

<Reveal summary="A worked example of Subject-centric triage" variant="example">
An alert fires: a developer account ran a database export at 22:30. Generic anomaly detection (environment-wide) might tune this out: developers query the database routinely, late-evening work happens, the export volume is within thresholds.

Subject-centric triage zooms in:

- **This developer's** baseline shows they have never queried this specific database before.
- **This developer's** historical working hours are 09:00 to 18:00. The 22:30 timing is four hours outside their normal window.
- **This developer's** other recent activity includes account permission changes that look like preparation.
- The peer group (other developers on the same team) shows no parallel activity. This is one developer doing something unusual on their own.

Each individual signal is below the environment-wide threshold. The combination, in the context of *this specific entity*, is a high-confidence Subject-level anomaly. That is what Subject-centric triage adds.
</Reveal>

# Implementation considerations

- **Tooling.** UEBA platforms (Microsoft Defender XDR, Exabeam, Securonix) handle entity baselining out of the box. SIEMs can do it with custom rules but at higher operational cost.
- **Feedback loop.** Analysts mark false positives. The system learns. Without that loop, baselines drift into noise.
- **Privacy.** Detailed per-entity behavior modeling has implications beyond security. Coordinate with legal, HR, and works councils where relevant.
- **Documentation.** When an anomaly fires, capture the baseline value it deviated from. That data is what defends the triage decision later.

<KeyTakeaway>
The behavioral framework is the difference between "an alert fired" and "this specific entity is doing something this specific entity does not normally do." The second is far more useful, and it is what Subject is designed to surface.
</KeyTakeaway>
