<Quiz title="Subject chapter quiz" subtitle="No grades. The point is to push your thinking.">

  <QuizItem
    prompt="An alert names one user. How many subjects should the analyst usually profile?"
    options={[
      { value: "one",     label: "One. The user named in the alert." },
      { value: "two",     label: "Two. The user and their host." },
      { value: "many",    label: "As many as the activity touches: user, host, service accounts, federated identities, downstream systems." },
      { value: "depends", label: "Depends on severity. Skip Subject for low-severity alerts." },
    ]}
    answer="many"
    explanation="Modern identity is plural. Behind any named user are typically several non-human identities (service accounts, cloud roles, federated SSO) that share trust paths. The Subject phase profiles all of them, not just the one the alert named."
  />

  <QuizItem
    prompt="Which of the four dimensions is most often skipped, and why does that matter?"
    options={[
      { value: "auth",    label: "Authentication. It is too rarely abnormal to be worth checking." },
      { value: "authz",   label: "Authorization. The check looks fine in a glance but hides toxic permission pairings and recent role changes." },
      { value: "behav",   label: "Behavior. Baselines are too unstable to be trusted." },
      { value: "rel",     label: "Relationships. They are too time-consuming to map." },
    ]}
    answer="authz"
    explanation="Authorization is the dimension where 'the action maps to the role' obscures the deeper question of whether the role itself is right and whether the permissions combine in unsafe ways. Toxic pairings and recent role changes are common gaps."
    hint="Think about the dimension that looks fine at first glance but rewards a second look."
  />

  <QuizItem
    prompt="A service account suddenly logs in interactively at 02:30. Which entity type pattern does this match?"
    options={[
      { value: "normal",    label: "Normal. Service accounts log in." },
      { value: "compromise",label: "Compromise signal. Service accounts are non-interactive by design; interactive logins are near-canonical for credential theft." },
      { value: "policy",    label: "A policy violation but not security-relevant." },
      { value: "test",      label: "A test run. Probably the on-call engineer." },
    ]}
    answer="compromise"
    explanation="Service accounts have predictable, non-interactive behavior by design. Interactive logins on a service account almost always mean the credential is being used in a way it was not intended for, and that is a high-confidence Subject signal."
  />

  <QuizItem
    prompt="What is the difference between insider risk and insider threat?"
    options={[
      { value: "same",     label: "Same thing. Different vocabulary." },
      { value: "intent",   label: "Risk is the possibility of harm regardless of intent. Threat is intentional harm. The methodology starts with risk and escalates to threat only with evidence." },
      { value: "severity", label: "Risk is low severity. Threat is high severity." },
      { value: "scope",    label: "Risk is internal. Threat is external." },
    ]}
    answer="intent"
    explanation="The distinction is about intent. Most insider risk is unintentional (mistakes, workarounds, policy violations). Insider threat is intentional. The methodology takes risk seriously as a category of its own and reserves the 'threat' designation for cases where evidence supports it. That distinction shapes escalation and how the rest of the organization is engaged."
  />

  <QuizItem
    prompt="The behavioral framework's most useful question is..."
    options={[
      { value: "env",    label: "Is this unusual in the environment?" },
      { value: "entity", label: "Is this unusual for this specific entity?" },
      { value: "peer",   label: "Is this unusual compared to peers in the same role?" },
      { value: "both",   label: "The framework asks both per-entity and peer-group questions, and the disagreement between them is itself a signal." },
    ]}
    answer="both"
    explanation="Per-entity baselining and peer-group baselining each catch different things. An entity drifting from its own history is one signal. An entire role drifting is another. The framework uses both, and when they disagree, that disagreement is informative."
    hint="A trick question. The two are not mutually exclusive."
  />

</Quiz>
