  <QuizItem

  <QuizItem
    prompt="A service account suddenly logs in interactively at 02:30. Which entity type pattern does this match?"
    options={[
      { value: "normal",    label: "Normal. Service accounts authenticate constantly; the hour is only unusual for humans." },
      { value: "compromise",label: "A compromise signal. Service accounts are non-interactive by design; this is near-canonical." },
      { value: "policy",    label: "A policy violation for the account owner to fix, but not itself security-relevant." },
      { value: "test",      label: "Probably the on-call engineer running a manual test with the account's credentials." },
    ]}
    answer="compromise"
    explanation="Service accounts have predictable, non-interactive behavior by design, which makes an interactive login a high-confidence Subject signal: the credential is being used outside its designed lane. It is a signal, not proof. Break-glass procedures and an admin troubleshooting with the service credential produce the same event, so the next check is who initiated the session and whether a sanctioned reason (a change ticket, a break-glass record) exists."
  />

  <QuizItem
    prompt="An egress alert flags a workstation making sustained connections to an external host on port 443. What is the entity-type question to ask about this network identifier?"
    options={[
      { value: "rare",    label: "How rare port 443 is in the environment. Uncommon ports are the primary tunneling signal." },
      { value: "conform", label: "Whether the traffic actually conforms to the protocol the port implies. SSH or DNS riding 443 is the classic bypass." },
      { value: "rep",     label: "Whether the destination IP has a clean reputation. A clean score clears the connection." },
      { value: "defer",   label: "None yet. Protocol analysis is deep-evidence work that belongs to Uncover, not Subject." },
    ]}
    answer="conform"
    explanation="Port 443 is the most common port on the internet, so rarity carries no signal at all. The signal is protocol/port mismatch: traffic on 443 that is not actually TLS, or DNS on an arbitrary high port, is the classic bypass pattern, because attackers pick common ports precisely to blend in. Reputation helps but does not clear anything; a clean destination means only that it has not been caught yet."
    hint="Attackers choose common ports on purpose."
  />

  <QuizItem
    prompt="What is the difference between insider risk and insider threat?"
    options={[
      { value: "same",     label: "The same thing. The two terms are interchangeable vocabulary for insider cases." },
      { value: "intent",   label: "Risk is possible harm regardless of intent; threat is intentional, shown by evidence." },
      { value: "severity", label: "Severity tiers: risk describes low-severity cases, threat describes high-severity ones." },
      { value: "scope",    label: "Direction: insider risk comes from inside, insider threat from outside partners." },
    ]}
    answer="intent"
    explanation="The distinction is about intent. Most insider risk is unintentional (mistakes, workarounds, policy violations). Insider threat is intentional, and the methodology reserves that designation for cases where evidence supports it. Two calibrations: the label is a revisable hypothesis, not a verdict (and NIST's insider-threat definition includes unwitting actors, so check your organization's vocabulary), and the label shapes who gets engaged, never whether confirmed harmful activity gets a response. Containment and escalation trigger on act, asset, and impact; intent is resolved in parallel."
  />

  <QuizItem
    prompt="An engineer's activity is consistent with their own 90-day baseline but looks nothing like anyone else's in the same role. What does the behavioral framework say?"
    options={[
      { value: "clear",  label: "Their own baseline clears it. Per-entity comparison is the framework's primary question." },
      { value: "peer",   label: "The peer mismatch overrides the personal baseline. Escalate on the role comparison alone." },
      { value: "signal", label: "The disagreement between the two baselines is itself a signal, so investigate what explains it." },
      { value: "noise",  label: "Peer comparison across engineers is noise. Roles vary too much for the mismatch to matter." },
    ]}
    answer="signal"
    explanation="Per-entity baselining is the framework's headline question, and here it passes. But the framework also runs the peer-group comparison, and when the two disagree, the disagreement is informative: it can mean a legitimately unusual job, or a baseline that was poisoned by long-running compromise before the window began. Neither baseline overrides the other; the gap between them is what deserves the look."
    hint="Two baselines, one entity, and they disagree. That fact is data."
  />

  <QuizItem
    prompt="An insider bulk-exports a customer database, then clears their shell history and deletes the staged archive. Under the Insider Threat Matrix, where does the history-clearing evidence belong?"
    options={[
      { value: "motive",   label: "Motive. Hiding the activity reveals why the insider acted in the first place." },
      { value: "means",    label: "Means. Shell access is the capability that made the whole export possible." },
      { value: "prep",     label: "Preparation. Cleanup is part of setting up the operation to survive scrutiny." },
      { value: "af",       label: "Anti-forensics. Destroying evidence of the act after the fact is its own section." },
    ]}
    answer="af"
    explanation="The matrix organizes insider tradecraft into sections: motive (why), means (what made it possible), preparation (setting it up), infringement (the harmful act, here the bulk export), and anti-forensics (concealing or destroying evidence afterward). History-clearing and deleting staged archives are textbook anti-forensics, and their presence upgrades the case: deliberate evidence destruction is among the strongest intent signals available. It still gets verified rather than assumed — scheduled cleanup jobs, retention scripts, and shell configurations that trim history all exist, so the analyst confirms the mechanism was manual before treating the cleanup as a confession."
  />

  <QuizItem
    prompt="A marketing team under deadline converted confidential documents into image files to get them past a slow approval tool and shared them externally, exposing customer data. What does Subject classify this as?"
    options={[
      { value: "threat",    label: "Insider threat. Customer data was deliberately moved outside the boundary; intent is irrelevant." },
      { value: "risk",      label: "Insider risk: no intent to harm. The exposure is still contained, clocked, and reported; the lasting fix is process." },
      { value: "neither",   label: "Neither. Data exposure through sanctioned sharing channels is a DLP tuning problem, not Subject's." },
      { value: "escalate",  label: "Both at once. Classify as insider threat by default until the investigation proves otherwise." },
    ]}
    answer="risk"
    explanation="Insider risk is the right label: the workaround was about getting work done past a slow tool, not about stealing data. But the label only decides the long-term fix, not the immediate response. Customer data left the boundary through a deliberate control bypass, so the exposure is scoped and contained, the regulatory notification question is asked (a notification clock does not care about motive), and the DLP bypass is recorded as a confirmed policy violation. What the risk classification changes is what happens after: process improvement, a faster approved sharing path, instead of an enforcement action that would add friction without fixing the cause. (The scenario is an illustrative composite, not a published incident.)"
    hint="The vocabulary matters. Risk and threat are not interchangeable."
  />

  <QuizItem
    prompt="A binary on a developer's laptop disables its sandbox at runtime, makes encrypted outbound network calls, and matches signatures used by the Empire toolkit. Subject's most likely conclusion is..."
    options={[
      { value: "block",     label: "Block and contain immediately. A toolkit signature match on a developer host is conclusive." },
      { value: "context",   label: "Read context first: signing, install path, peer baseline, documented runtime mode, then verdict." },
      { value: "isolate",   label: "Isolate the device and hold it for a forensic image before touching any other dimension." },
      { value: "escalate",  label: "Escalate under insider-threat protocols, since the developer installed the flagged binary." },
    ]}
    answer="context"
    explanation="A signature match alone is not Subject's verdict. The four dimensions plus access scope plus operational risk produce the picture. A signed, vendor-installed, peer-baselined binary running in a documented configuration on a developer workstation reads very differently from the same activity from an unsigned binary in a user-writable directory. Subject's job is to record that distinction defensibly, not to react to the signature alone."
  />

  <QuizItem
    prompt="Subject hands its entity map to Scope. Which entities belong on it?"
    options={[
      { value: "named",      label: "Only the entity named in the alert. The map is a pointer; Scope rebuilds the rest." },
      { value: "suspicious", label: "Every entity with a suspicious finding. Cleared entities are dropped to keep the map actionable." },
      { value: "all",        label: "Primary, secondary, and downstream entities, each with its dimension assessment, including the ones ruled out." },
      { value: "human",      label: "The human identities only. Service accounts and hosts are infrastructure, tracked elsewhere." },
    ]}
    answer="all"
    explanation="The map carries three rings: primary entities directly named or implicated, secondary entities connected through trust paths (service accounts, federated identities, peers on the same host), and downstream entities the implicated identities can reach, each with its authentication, authorization, behavior, and relationships assessment. Confidence labels ride alongside in the baselines-and-deviations artifact, using the shared rubric. And ruled-out entities stay on the map, because examined-and-cleared is a finding: dropping them invites the next phase to spend depth re-answering a question Subject already closed."
    hint="Think about what Scope would have to redo if the map only listed the suspicious entities."
