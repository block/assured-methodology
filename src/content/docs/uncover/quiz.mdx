<Quiz title="Uncover chapter quiz">

  <QuizItem
    prompt="A threat intel feed says a particular domain is associated with a known campaign. The analyst sees the same domain in firewall logs from one host. What is the right next step?"
    options={[
      { value: "block", label: "Block the domain at the perimeter now; a campaign association is action-worthy on its own." },
      { value: "validate", label: "Treat the match as a hypothesis: check which process connected and whether the pattern fits." },
      { value: "ignore", label: "Ignore it. Campaign domains rotate too fast for a feed match to mean anything locally." },
      { value: "share", label: "Post the intel to the team channel and let the host's owner decide whether to look." },
    ]}
    answer="validate"
    explanation="Threat intelligence is most useful as a hypothesis. The matched domain is a starting point, not a verdict. Validate against the actual telemetry (which process, which user, which pattern) before acting."
  />

  <QuizItem
    prompt="Which level of MITRE ATT&CK changes most often?"
    options={[
      { value: "tactics", label: "Tactics" },
      { value: "techniques", label: "Techniques" },
      { value: "procedures", label: "Procedures" },
      { value: "all-same", label: "All change at the same rate." },
    ]}
    answer="procedures"
    explanation="Procedures (specific implementations) change rapidly as adversaries adapt their tooling. Techniques (the methods) change more slowly. Tactics (the goals) are nearly stable over years. This is why TTP-based hunting beats indicator matching for durability."
  />

  <QuizItem
    prompt="An investigation needs to know whether a file was executed on an endpoint earlier this week. Which data source answers this most directly?"
    options={[
      { value: "siem", label: "SIEM" },
      { value: "edr", label: "EDR" },
      { value: "fim", label: "FIM" },
      { value: "network", label: "Network analysis" },
    ]}
    answer="edr"
    explanation="EDR captures process creation events that show whether a file was executed, and a few days is comfortably inside a typical retention window. FIM tells you the file exists or was modified, but not whether it ran. SIEM aggregates from other sources. One caveat worth knowing: for questions like did this ever run, beyond the EDR retention window, the answer lives in whatever long-term store (SIEM or data lake) archives the EDR telemetry."
  />

  <QuizItem
    prompt="The Uncover narrative concludes with a chain of MITRE techniques. Why is the chain more useful than free-form prose?"
    options={[
      { value: "shorter", label: "It is shorter, and shorter records are what downstream readers actually finish." },
      { value: "portable", label: "It is a shared vocabulary that IR, detection engineering, and trend analysis all recognize." },
      { value: "required", label: "Most compliance frameworks require ATT&CK mappings in escalated-incident records." },
      { value: "easier", label: "It is easier to write correctly under time pressure than a free-form narrative is." },
    ]}
    answer="portable"
    explanation="ATT&CK turns analyst observations into a portable artifact. The same chain of techniques is meaningful to the IR responder, the detection engineer who decides what to tune, and the leader who wants to see threat trends over time."
  />

  <QuizItem
    prompt="An analyst is investigating a possible compromise on a macOS developer workstation. The user's role legitimately involves scripting, IDE plugin processes, and encrypted outbound traffic. What does the methodology require Uncover to produce if the evidence supports a false-positive verdict?"
    options={[
      { value: "dismiss", label: "Nothing beyond the closure itself. A false-positive verdict ends the Uncover obligation." },
      { value: "evidenced", label: "The same rigor as a positive finding: evidence chain, confidence, coverage gaps, feedback." },
      { value: "shorten", label: "A one-line entry, 'false-positive, developer tooling', in the case notes before closing." },
      { value: "escalate", label: "An escalation anyway; surface-suspicious activity should get an IR review before closing." },
    ]}
    answer="evidenced"
    explanation="A false-positive verdict that meets the methodology's standard is not dismissed. It is documented, evidenced, and bounded. That documentation is what lets the case re-open with full context if new signals appear, and what produces the detection-engineering feedback that prevents the same alert from firing repeatedly."
  />

  <QuizItem
    prompt="Risk receives an Uncover handoff. Which of these decisions is Risk authorized to make?"
    options={[
      { value: "isolate", label: "Isolate the compromised host before the adversary can react to detection." },
      { value: "notify", label: "Start regulator notification if the evidence shows regulated data was touched." },
      { value: "binary", label: "Close with confidence, or push back to Scope to expand. Risk decides; it does not act." },
      { value: "tune", label: "Tune the detection rule that fired so the same alert stops consuming the queue." },
    ]}
    answer="binary"
    explanation="Risk is the analytical checkpoint, not the response phase. Its job is to evaluate whether Uncover's evidence is sufficient to close the case or whether the investigation needs to expand. Containment, notification, and detection tuning happen in later phases (Escalation, Documentation) once Risk's verdict supports them."
    hint="Risk is not response."
  />

  <QuizItem
    prompt="EDR records powershell.exe (PID 4416) opening an outbound connection at 14:22:31Z. The proxy logs a TLS session from the same host to a newly registered domain at 14:22:31Z. What makes treating these as one event defensible?"
    options={[
      { value: "time", label: "The identical timestamp. Two sources agreeing to the second is the correlation." },
      { value: "joins", label: "The join keys agree: same host, same second, and the process's destination matches the proxy's." },
      { value: "domain", label: "The domain's age. A newly registered destination makes any nearby telemetry part of the case." },
      { value: "edr", label: "Nothing extra is needed. Once EDR attributes the connection to a process, the proxy adds nothing." },
    ]}
    answer="joins"
    explanation="Correlation is defensible when independent sources agree on the keys that identify the event: the host, the time, and the connection endpoints. A timestamp alone can collide, hosts make many simultaneous connections, and the proxy adds what EDR cannot see (the URI, TLS details, and bytes transferred). The worked example does exactly this: the firewall session matching the EDR network event to the second is what turns two log lines into one attributed action."
    hint="One matching field is coincidence-prone. Which fields together identify the event?"
  />

  <QuizItem
    prompt="The case needs to answer one question before Risk: did data actually leave the environment? Which evidence combination answers it?"
    options={[
      { value: "edr", label: "EDR alone. Process telemetry shows file reads and network sends from the same process tree." },
      { value: "egress", label: "Egress telemetry (proxy, DLP, cloud data events) aligned against the endpoint timeline." },
      { value: "intel", label: "Threat intelligence. If the actor's campaigns exfiltrate, treat exfiltration as established." },
      { value: "vuln", label: "The vulnerability scanner, which shows whether an exfiltration-capable exposure existed." },
    ]}
    answer="egress"
    explanation="Exfiltration is proven at the boundary, not on the endpoint. EDR shows a process read files and sent bytes, but volume, destination, and content classification live in the egress path: proxy or firewall session sizes, DLP verdicts, and cloud-side data events for storage services. Aligning those against the endpoint timeline is what turns 'the process could have exfiltrated' into 'this much data moved to this destination at this time', or into a documented negative finding."
  />

</Quiz>
