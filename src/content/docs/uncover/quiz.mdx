  <QuizItem
    prompt="EDR records powershell.exe (PID 5208) opening an outbound connection at 14:22:31Z. The proxy logs a TLS session from the same host to a newly registered domain at 14:22:31Z. What makes treating these as one event defensible?"
    options={[
      { value: "time", label: "The identical timestamp. Two independent sources agreeing to the second is the correlation." },
      { value: "domain", label: "The domain's age. A newly registered destination pulls any nearby telemetry into the case." },
      { value: "joins", label: "The join keys agree: same host, same second, same connection (destination or client port)." },
      { value: "edr", label: "Nothing extra. Once EDR ties the connection to a process, the proxy record adds nothing." },
    ]}
    answer="joins"
    explanation="Correlation is defensible when independent sources agree on the keys that identify the event: the host, the time, and the connection. A timestamp alone can collide and hosts make many simultaneous connections. The proxy adds what EDR usually cannot see: the requested hostname (from the CONNECT line or the TLS SNI), TLS metadata, and bytes transferred, plus the full URI only where the proxy decrypts TLS. Behind an explicit proxy, EDR records the proxy's own address as the destination, so the join becomes host, time, and client source port (where the proxy logs it). The worked example does exactly this: the proxy session matching the EDR network event on host, client source port, and time is what turns two log lines into one attributed action. The source port only joins cleanly where nothing translates addresses between the host and the log source; behind NAT, match on the translated tuple or fall back to host, time, and destination."
    hint="One matching field is coincidence-prone. Which fields together identify the event?"
    source={{ href: "/docs/uncover/correlation/#join-keys-how-two-events-meet", label: "Correlation and the timeline: join keys" }}
